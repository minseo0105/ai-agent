# MONEY:ON Phase 3 — 어린이 화면과 금융 친구

## 1. 기존 화면의 문제점

실제 코드와 화면을 확인했을 때 어린이 상단에 10개 탭, 하단에 5개 메뉴가 함께 있었다. 통장·기입장·소비 내역이 나뉘고, 잔액 카드와 계좌 카드, 가상 소비 카드와 안내가 반복되었다. 통장을 보고 기록하는 핵심 행동보다 탐색과 설명에 많은 공간을 사용했다. 보상과 통장 금액도 여러 카드 사이에서 비교해야 했다.

기존 금융 원장은 이미 정확한 계좌 분개를 제공하므로 거래 기능을 다시 만들지 않고 표시·동선만 재구성했다.

## 2. 개선한 정보구조

| 하단 메뉴 | 기본 화면 | 연결되는 기능 |
|---|---|---|
| 홈 | 이름·캐릭터, 큰 통장 잔액, 저금통/예상 보상, 두 개의 주요 버튼, 최근 거래 최대 3개, 짧은 코치 메시지 | 돈 썼어요, 통장 보기, 나의 성장 |
| 통장 | 현재 잔액, 전체 받은 돈/사용한 돈, 입출금 내역 | 거래 펼치기, 소비 분류 수정·필터, 직접 기록 |
| 저축 | 저금통 금액, 목표와 달성률, 예상 보상 | 금고 입출금, 목표 만들기, 이자 알아보기 |

기입장은 통장의 내역·분류 기능으로 통합했다. 홈의 **나의 성장** 안에 정원·퀘스트·배지를 두었다. 이자 실험과 기존 구매 전 계산은 저축의 **이자 알아보기**에서 금액을 움직이거나 직접 입력해 사용할 수 있다. 가상 가맹점 소비는 **돈 썼어요 → 가상 소비로 연습하기** 안에 보존했다.

홈의 잔액은 `state.banking.accounts`의 실제 Mock Ledger wallet 잔액이며 임의 초기값을 표시하지 않는다. 저금통도 vault 계좌를 사용한다. 예상 보상은 서버 주기 결과의 `interest`를 사용하고 **예상 금액 · 아직 안 들어왔어요**라고 표시한다. 부모 승인 대기 중인 종료 주기의 예상 보상도 표시하되 지갑에 합산하지 않는다.

통장 합계는 같은 계좌 내역을 조회하는 표시용 집계다. 받은 돈에는 용돈·부모 보상을, 사용한 돈에는 소비와 취소 역거래를 반영한다. 금고 이동을 소비액에 넣지 않는다. 상세에서 거래일·거래처·금액·카테고리를 확인하며 분류 정정은 기존 API에 요청한다. DEMO 계좌 ID 등은 기본 화면에서 숨기고 통장 정보에서만 확인할 수 있다.

## 3. 우루미 적용 결과

기본 표시명은 **우루미**, 영문 시안은 **WOORUMI**, 메시지는 **내 돈을 함께 키워주는 작은 금융 친구**다. 기존 코치의 제품 화면 이름을 공통 설정으로 대체했다. 자녀의 별명처럼 사용자가 저장한 실제 데이터는 이름이 같더라도 바꾸지 않았다.

`web/src/lib/moneyonCoach.ts`의 `COACH_BRAND`가 표시명·영문명·태그라인·시안 안내를 관리한다. 기본 이름을 이 파일에서 바꾸면 코치 이름, SVG 접근성 이름, 오류 도움말, 소개에 일괄 반영된다. 배포 시 이름만 바꾸고 싶으면 `NEXT_PUBLIC_MONEYON_COACH_NAME` 환경변수도 사용할 수 있다. Next.js의 공개 환경변수이므로 적용 후 다시 빌드해야 한다.

예:

```powershell
cd web
$env:NEXT_PUBLIC_MONEYON_COACH_NAME='우리모니'
$env:NEXT_BUILD_DIR='.next-moneyon'
npm run build
```

코인 모양의 자녀 프로필은 일반 프로필 캐릭터로 유지한다. 우루미는 별도의 둥근 민트빛 구름 친구로, 연하늘색 잎 장식과 아이보리 얼굴을 가진 오리지널 SVG다. 기존 우리금융 캐릭터나 로고·상표 이미지를 사용하지 않았다. 소개에는 **우리금융 공식 캐릭터가 아닌 오리지널 시안**임을 표시한다.

| 상태 | 표정/장식 | 실제 연결 |
|---|---|---|
| 인사 | 손을 흔드는 기본 표정 | 빈 통장·기본 안내 |
| 용돈 입금 | 웃는 눈·코인 | 원장에 용돈 입금이 있을 때 |
| 소비 안내 | 집중한 표정·기록장 | 기록 화면 또는 실제 소비 후 |
| 목표 달성 | 웃는 눈·별 | 서버 금고 잔액이 목표 금액에 도달했을 때 |
| 보상 설명 | 궁금한 눈·올린 눈썹 | 저축·읽기 전용 이자 실험 |
| 도움말 | 부드러운 걱정 표정·물음표 | 서버가 거절한 소비 등 실제 오류 |

`MoneyCoach` 인터페이스와 `ruleBasedCoach`를 분리했다. 이 계층에는 API·거래 수정 권한이 없고 서버가 제공한 금액을 짧게 설명한다. 보상 수식을 새로 계산하지 않는다. 상한이 적용된 보상도 서버 결과 그대로 안내한다. 외부 AI는 연결하지 않았다.

한 말풍선에는 한 가지 짧은 메시지만 표시한다. 소비 금액으로 평가하거나 형제와 경쟁시키지 않는다. 게임은 홈에서 분리했고, 로그인 보상·반복 보상·무한 퀘스트·루프 애니메이션을 추가하지 않았다. 이미 배운 선택형 퀘스트는 완료로 표시하고 재보상 버튼을 제공하지 않는다. 정원에는 부모님과 돈 이야기를 나누자는 안내를 둔다.

## 4. 디자인과 사용성

민트/블루/아이보리의 기본 스타일을 사용하고 모험 테마는 블루, 동물 마을 테마는 부드러운 핑크로 배경·버튼·말풍선을 바꾼다. 세 테마에서 우루미의 형태와 이름은 동일하다. 기존 자녀별 테마 저장값은 바꾸지 않는다.

큰 잔액, 단순한 두 행동, 일관된 선형 SVG 아이콘, 44px 이상의 주요 터치 영역, 한국어 폰트와 충분한 여백을 적용했다. 폼은 글자가 16px 이상인 입력을 사용한다. 주요 화면 전환 시 제목으로 포커스를 옮기며, 거래 상세는 기본 HTML details로 키보드 조작이 가능하다. 동작 감소 설정을 존중하고 과도한 애니메이션을 사용하지 않는다.

375px 검수에서 발견한 우주인 이모지의 두 글자 분리/가로 넘침은 SVG 우주인으로 표시해 해결했다. 저장된 프로필 값 `🧑‍🚀` 자체는 유지했다.

## 5. 기존 기능 유지와 금융 코드 보존

- 기존 PIN, 부모·아이 세션, 가족/아이 소유권, 부모 화면과 계좌·지급·승인을 유지한다.
- 용돈 지급·수동 지출·가상 소비·부모 보상·금고 이동은 기존 거래 API와 원장을 그대로 사용한다. 클라이언트는 기존 요청 키 재전송 방식을 공유한다.
- 목표·퀘스트·배지·XP·정원 단계는 기존 서버 데이터를 표시한다. 분류 정정, 테마, 보관된 아이, 데모 초기화·가상 날짜도 유지한다.
- 이자 실험은 기존 `/experiment` API만 사용한다. 실제 통장과 거래 기록이 바뀌지 않는 것을 브라우저에서 다시 확인했다.
- 작업 전후 아래 5개 파일의 SHA-256이 일치한다. 금융 거래·계산 코드 변경 및 DB 마이그레이션 추가가 없다.

```
services/moneyon.py
services/moneyon_accounts.py
services/moneyon_banking.py
services/moneyon_demo.py
api/moneyon.py
```

해시 증거: `reports/moneyon-phase3/financial-source-check.json`.

## 실행과 재검증

로컬 실행 방법과 인증 조건은 [기존 은행 프로토타입 문서](MONEYON_BANKING.md)의 실행 방법을 그대로 사용한다. 브랜치·운영 설정·원격 저장소는 변경하지 않았다.

```powershell
# 프로젝트 루트에서 새 UI 검사
node tests/test_moneyon_child_ui.cjs

# 웹 빌드
cd web
$env:NEXT_BUILD_DIR='.next-moneyon'
npm run build
npm run typecheck

# 다시 프로젝트 루트에서 실제 브라우저 검사
cd ..
node tests/test_moneyon_child_browser.cjs
node tests/test_moneyon_banking_browser.cjs
node tests/test_moneyon_browser.cjs
```

브라우저 검사는 기존 Playwright 도구와 설치된 Chrome을 사용한다. Phase 3 검사는 3109/8109 포트, 별도 테스트 DB `data/moneyon/phase3-browser-*`를 사용한다. 이름을 빌드 환경변수로 시험한 뒤 기본 시안으로 돌아가려면 해당 환경변수를 지우고 다시 빌드한다.

## 8. 미해결·미검증 사항

- 우루미는 검토용 이름/디자인 시안이다. 실제 우리금융 공식 브랜드 채택으로 표시하지 않았다. 브랜드 확정 시 공통 설정을 변경할 수 있다.
- 실제 어린이와 부모의 사용성 조사, 실제 iOS/Android 터치 기기 및 전체 스크린리더 검증은 수행하지 않았다. 현재 검증은 Chrome의 반응형 화면·키보드 기본 구조와 동작 감소 설정 범위다.
- 운영 인증·PIN 복구·영속 DB·대량 거래·페이지네이션과 실제 은행 연동은 이전 단계의 후속 과제로 남아 있다. 이번 UI 작업으로 완료된 것으로 표시하지 않는다.
- 기존 모든 에이전트의 외부 API 실사용/운영 데이터 회귀는 수행하지 않았다. 해당 범위는 기존 로컬 자동 검사와 빌드로 확인했다.
