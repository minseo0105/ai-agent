# ZIP 대시보드 1단계 설계 — 지도 대시보드 · 8단계 타임라인 · 투자금 시뮬레이터

작성일 2026-11-06 · 상태: **승인 대기** · 선행 문서: `docs/zipon_platform_diagnosis_2026-11-06.md`

## 1. 이해한 요구사항

**목표.** 사용자가 지도에서 개발구역을 고르면 한 화면에서 사업 단계, 거래 전 확인사항, 예상 투자금을 본다.

**이번 범위(하위 프로젝트 1).** 대시보드 레이아웃, 8단계 타임라인, 거래 전 체크포인트, 투자금 시뮬레이터, 4개 탭 구조.

**지킬 것(사용자 지정).** 기존 1,190건의 검색·필터·마커 유지 / 기존 DB 구조 유지 / 운영 DB 변경·배포는 별도 승인 / 실제 데이터가 없는 곳에 임의 값 표시 금지 / 검증된 Polygon이 없으면 마커 유지 / 법적 거래 가능 여부를 확정적으로 판정하지 않음 / 경계 활성화(2)와 실거래 연동(3)을 위해 화면 재설계가 필요 없는 구조.

**이번 범위 밖.** 실거래 조회·매칭, 사전진단 엔진, 구역 비교, 관심 구역·알림, 매물 연동, 경계 활성화.

- 마커·목록 클릭은 **양방향**: 마커 → 패널 열림 + 목록 스크롤, 목록/패널 → 지도 이동·선택 강조. 선택 상태는 하나(`selectedId`)이고 URL 해시(`#zone=<id>`)에 반영해 새로고침·링크 공유 때 복원한다.
- 패널은 `Esc`와 "← 목록" 버튼으로 닫는다. 패널이 열려도 필터·검색은 그대로 유지된다.

## 3. 사업 단계 타임라인

### 공식 데이터가 실제로 말해 주는 것

서울시 정비사업 정보몽땅 상세 페이지의 단계 목록은 **유형과 관계없이 같은 14단계**다(기본계획수립, 안전진단, 정비구역지정, 추진위원회승인, 조합설립인가, 사업시행인가, 관리처분인가, 철거신고, 착공신고, 일반분양승인, 준공인가, 이전고시, 조합해산, 조합청산). 각 단계는 날짜(없을 수 있음)와 현재 단계 표시만 가진다. 재개발·재건축 절차 차이는 공식 데이터에 담겨 있지 않으므로 **유형별 표준 흐름은 우리가 정의하는 안내 규칙**이고, 화면에 그렇게 표시한다.

### 표준 8단계와 공식 단계 매핑

| # | 표시 단계 | 공식 단계명 | 비고 |
|---|---|---|---|
| 1 | 정비구역 지정 | 정비구역지정 | |
| 2 | 추진위원회 승인 | 조합설립추진위원회승인 | |
| 3 | 조합설립 인가 | 조합설립인가 | |
| 4 | 사업시행계획 인가 | 사업시행인가 | |
| 5 | 관리처분계획 인가 | 관리처분인가 | |
| 6 | 이주·철거 | 철거신고 | 이주 시점은 공식 데이터에 별도 항목이 없음 → "이주: 정보 없음" |
| 7 | 착공 | 착공신고 | 일반분양승인은 보조 정보로 표시 |
| 8 | 준공·이전고시 | 준공인가, 이전고시 | 둘 다 날짜를 각각 표시 |

사전 단계(기본계획수립·안전진단)와 종료 단계(조합해산·청산)는 8단계 밖의 보조 줄로 표시한다. 해산·청산은 "사업 완료"가 아니라 별도 확인이 필요한 상태로 둔다(기존 정책 유지).

### 유형별 흐름 규칙(안내용, 법 해석 아님)

| 유형 | 규칙 |
|---|---|
| 재개발 | 안전진단은 일반적으로 거치지 않는 단계로 표시(`해당 없음`이 아니라 "일반적으로 거치지 않음·공식 자료에 기록 있으면 표시") |
| 재건축 | 안전진단을 사전 단계로 표시 |
| 소규모·가로주택 등 | 추진위·구역지정 생략 가능성을 안내(해당 단계에 "생략될 수 있음" 주석). 판정하지 않음 |
| 신속통합기획·모아타운 | **사업 유형이 아니라 정책 프로그램**이므로 타임라인 위에 프로그램 배지만 달고 흐름은 기본 유형을 따름(기존 `program` 분리 정책 유지) |

### 단계 상태(색·아이콘으로 구분)

| 상태 | 조건 | 표시 |
|---|---|---|
| **현재 단계** | 공식 현재 단계 | 강조(채운 원 + 라벨 "현재") |
| **완료(일자 확인)** | 현재 단계 이전 + 공식 날짜 있음 | 채운 체크 + 날짜 |
| **지난 단계(일자 미공개)** | 현재 단계 이전 + 날짜 없음 | 반쯤 채운 표시 + "일자 미공개" |
| **예정** | 현재 단계 이후 | 빈 원 |
| **공식 상세 미확인** | 목록 정보만 있는 사업 | 현재 단계 하나만 표시, 앞뒤 단계는 그리지 않고 "공식 상세 확인 전"이라고 안내 |

진행 표기는 임의의 백분율이 아니라 **"8개 주요 단계 중 4단계 도달 (일자 확인 3)"** 형식이다. 공식 현재 단계는 "그 인가를 받은 상태"를 뜻하므로 현재 단계까지를 "도달"로 센다.

### 각 단계에 표시하는 항목

단계명 · 상태 · 실제 인가·고시일(원문 날짜, 정밀도 표기) · 주요 의미 · 다음 단계 · 공식 출처 링크(사업 상세 페이지, 단계별 문서 링크는 **제공되지 않음**으로 표시) · 거래·권리 확인 질문(§5).

향후 일정은 표시하지 않는다(공식 일정 없음).

## 4. 거래 전 체크포인트 카드

- 내용: 현재 단계에서 확인할 항목 3~5개(기존 `stage_guide.checks` + `investor_guide.watch_next` 재사용), "다음 단계에서 달라지는 점", "이 사업에서 확인된 값이 아니라 일반 안내"라는 문구, 면책.
- 표현은 **질문형**이다("조합원 지위 승계가 가능한지 확인"). "거래 가능/불가" 같은 단정 문구는 쓰지 않는다. 규제·예외 조문을 인용하는 문구는 법령 검증이 끝나는 하위 프로젝트 4에서 추가한다.

## 5. 투자금 시뮬레이터

### 입력(모두 사용자 입력, 기본값 없음)

매입가격 · 종전자산 감정평가액 · 비례율(%) · 조합원 분양가 · 취득 관련 비용(합계) · 대출금액 · 금리(연 %) · 보유기간(개월) · 기타 비용 · 가정 준공 후 시세. 단위는 만원이다.

### 계산식(화면에 그대로 표시, 사용자가 확인)

```
예상 권리가액     = 종전자산 감정평가액 × 비례율
예상 추가분담금   = 조합원 분양가 − 권리가액           (음수면 환급 예상, 별도 표시)
금융비용          = 대출금액 × 금리 × 보유기간(개월) ÷ 12   (단순 이자, 분할상환·복리 미반영)
총투자금          = 매입가격 + 취득 관련 비용 + 추가분담금(양수일 때) + 금융비용 + 기타 비용
                    (추가분담금이 음수이면 환급액만큼 총투자금에서 차감)
자기자본 투입액   = 총투자금 − 대출금액
가정 손익         = 가정 준공 후 시세 − 총투자금
가정 수익률       = 가정 손익 ÷ 자기자본 투입액
```

### 시나리오

기준 / 보수 / 낙관 3열을 나란히 비교한다. 보수·낙관은 기준 입력에 **조정폭**을 더해 계산하고, 조정폭도 화면에서 수정할 수 있다.

| 조정 항목 | 보수 기본 | 낙관 기본 |
|---|---|---|
| 비례율 | −5%p | +5%p |
| 조합원 분양가 | +5% | −3% |
| 가정 준공 후 시세 | −10% | +10% |
| 보유기간 | +12개월 | −6개월 |
| 금리 | +1%p | −0.5%p |

이 기본 조정폭은 **예시 가정이며 사실이 아님**을 화면에 명시한다(수정 가능, 초기화 버튼 제공).

### 입력 검증과 특수 상황

- 필수 입력(감정평가액·비례율·분양가)이 없으면 권리가액·분담금 칸은 `입력 필요`로 두고 값을 만들지 않는다. 선택 입력이 비면 0으로 계산하되 "미입력 항목: …"을 결과 위에 표시한다.
- 비례율이 일반적인 범위를 크게 벗어나면(예: 0 이하 또는 200% 초과) 계산은 하되 "입력값 확인" 경고를 표시한다.
- 추가분담금이 음수(환급), 0, 양수 세 경우의 문구를 구분한다. 확정 수익이 아니라 가정 기반 추정치임을 결과 영역에 항상 표시한다.
- 입력값은 사업별로 브라우저(`localStorage`)에 저장한다. 접근 실패 시에도 화면은 정상 동작한다.

## 6. 데이터와 API (기존 구조 유지, DB 변경 없음)

### 문제

지도 목록 RPC(`zipon_development_map`)는 면적·세대수·고시일을 내려주지 않는다. RPC를 바꾸려면 운영 DB 변경이 필요하다.

### 해결: 읽기 전용 상세 조회 1개 추가

`GET /api/realestate/development/projects/{project_id}` — 기존 REST 조회 경로(`rm._remote_request`)로 해당 1건만 읽는다.

| 응답 블록 | 원천 | 설명 |
|---|---|---|
| `project` | `development_projects` | 기존 `present_project()` 결과 + 면적(`area_m2`)·예정 세대수(`planned_units`)·고시일(`notice_date`)·공식 기준일(`source_date`). 값이 NULL이면 NULL 그대로 |
| `process_timeline` | 신규 `services/development_timeline.py` | §3의 8단계 구조(순수 함수, 서버에서 계산해 테스트 가능) |
| `sources` | `development_project_sources` | 공식 출처 이름·URL·**수집일시**·검증일시 |
| `recent_updates` | `development_updates` | 최근 변경 이력 5건(단계 변경 등). 알림(5단계)의 원천이기도 함 |
| `connections` | 서버 상수 + 실제 상태 | 아래 표 |

목록 응답(1,190건)은 커지지 않는다. 상세는 구역을 골랐을 때만 1건씩 조회한다. 실패하면 목록 데이터만으로 요약을 보여주고 상세 영역에 오류를 표시한다.

### `connections` — 화면이 상태를 하드코딩하지 않게 하는 확장점

```
connections: {
  trades:   { state: "PARTIAL",
              linked_types: ["아파트","연립·다세대","단독·다가구","오피스텔"],
              unlinked: ["토지"],
              zone_matching: "BLOCKED_NO_VERIFIED_BOUNDARY" | "AVAILABLE" },
  rights_engine: { state: "NOT_CONNECTED" },
  listings:      { state: "NOT_CONNECTED" }
}
```

2단계(경계)·3단계(실거래)가 완료되면 **서버가 이 값을 바꾸고**, 화면은 `state`에 따라 같은 탭에 내용을 채운다. 탭 구조와 컴포넌트는 바뀌지 않는다.

**기존 코드 변경:**
- `DevelopmentTab.tsx`: 데이터 로딩·필터·신선도 로직을 훅 `useZiponDevelopment`로 분리(동작 변경 없음)하고, 화면은 `ZipDashboard`가 맡는다.
- `ZiponMap.tsx`: ① 높이를 컨테이너에 맞추는 `fill` 모드, ② 선택 사업으로 이동·강조(`focusId`), ③ 클러스터 렌더링, ④ 선택 구역이 있을 때 패널 폭만큼 중심을 보정. 검증된 경계 Polygon 렌더링과 `INSIDE 판정 안 함` 원칙은 그대로.

**확장 자리(구현은 안 함, 타입과 props만):**
- 경계: `ZiponMap`은 이미 `point.boundary`가 검증되면 Polygon을 그린다. 2단계 후 데이터가 채워지면 코드 변경 없이 표시된다. 단계별 색은 지금 마커 색 체계를 Polygon 채움에도 사용.
- 실거래: `ZiponMap`에 선택적 `tradeMarkers` prop(없으면 아무것도 안 그림), `TradesTab`에 `trades?: ZoneTrade[]`. `ZoneTrade.zone_relation`은 `INSIDE_CONFIRMED | NEARBY_ESTIMATED | UNKNOWN`(요구사항의 3분류).
- 권리: `RightsAssessment`는 결과 `NO_LIMITATION_FOUND | NEEDS_CHECK | LEGAL_RISK`, 근거·법령·기준일·부족한 정보 필드를 가진다. 엔진이 없는 지금은 아무것도 판정하지 않는다.

## 8. 디자인 방향

- 흰 배경, 단일 브랜드 포인트 컬러(**퍼플**)를 새 토큰으로 추가(`--zip`, `--zip-soft`). 다크모드 값도 정의. 다른 서비스 색은 건드리지 않음.
- 숫자·상태 위계: 큰 숫자(권리가액·총투자금), 상태 칩, 출처·기준일은 작은 보조 텍스트.
- 패널 전환: 선택 시 목록 → 상세 슬라이드(150ms), `prefers-reduced-motion`이면 즉시 전환.
- 접근성: 탭은 `role="tablist"`, 방향키 이동, 지도 위 모든 조작에 키보드 대안(목록).

## 9. 테스트 계획

| 영역 | 방법 |
|---|---|
| 타임라인 규칙 | Python 단위 테스트: 재개발·재건축·프로그램 배지, 날짜 있음/없음, 목록 기반(단계 1개), 해산·청산, 공식 상세 미확인 |
| 상세 API | Python 테스트(REST 가짜 응답): NULL 필드, 출처 없음, 조회 실패, 권한(익명 접근 불가 기존 설정 유지) |
| `connections` | 경계 0건일 때 `BLOCKED_NO_VERIFIED_BOUNDARY` |
| 계산 | `investmentCalc.ts` 순수 함수를 Node 내장 테스트 러너로 검증: 음수 분담금, 0, 필수값 없음, 단위, 시나리오 조정, 경계값 |
| 클러스터 | 같은 점 좌표, 줌별 개수, 선택 항목 보존 |
| 회귀 | 기존 집온 Python 테스트 733개, `test_frontend_ux.py`의 소스 문자열 검사(필요한 것만 의도적으로 갱신하고 이유 기록), 프론트 typecheck·build |
| 화면 | Playwright로 1440 / 768 / 390px 캡처(API는 가짜 응답) |

**한계(미리 밝힘).** 샌드박스에서는 NAVER 지도 SDK에 접속할 수 없어 캡처에는 지도 대신 대체 영역이 보인다. 실제 지도 렌더링은 배포 후 확인이 필요하다.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| `test_frontend_ux.py`가 소스 문자열을 직접 검사해 구조 변경에 깨짐 | 깨지는 항목을 먼저 목록화, 의도된 변경만 갱신 |
