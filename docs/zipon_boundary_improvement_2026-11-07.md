## 4. 중복 레이어 처리 (병합하지 않음)
- 공식 레이어는 한 사업을 신속통합·재개발/재건축·재정비촉진구역 분류로 여러 행에 쌓아 둔 경우가 많다. AMBIGUOUS 중 근거를 계산한 283건:
  | 구분 | 건수 |
  | --- | ---: |
  | 같은 이름 + 도형 IoU ≥ 0.9 (쌓인 행으로 보임) | **185** |
  | 같은 이름이지만 IoU < 0.9 | 23 |
  | 이름이 서로 다른 후보(부분 포함) | 75 |
  | **자동 병합** | **0** |
- 185건은 `DUPLICATE_LAYER_ROWS_FOR_REVIEW`로 표시하고 후보 레코드 ID·분류·IoU를 근거로 남긴다. **도형이 같아도 같은 사업이라고 단정하지 않으며**, 사람이 확인한 뒤에만 하나로 본다. 확인되면 최대 +185건이 후보가 될 수 있으나 이는 추정 상한이다(사람 검토 전에는 자동 후보에 넣지 않는다).

## 5. 매칭 불가의 원인: 진행 단계 (추가 승인된 SELECT 결과)
- `status` 컬럼은 1,190건 모두 `UNKNOWN`이라 쓸 수 없다. 단계(`stage_raw`)로 확인했다.
- 종결·말기 단계(조합해산·조합청산·이전고시·준공인가) 236건 중 **NO_MATCH 176건(74.6%)**, EXACT 32, REVIEW 28. 공식 레이어가 "진행 중 현황"이라 완료·해산 사업이 빠져 있다는 가설이 확인됐다.
- 조합해산 98건 중 NO_MATCH 73, 조합청산 58건 중 45, 이전고시 50건 중 44. 추진위원회승인(152건)도 NO_MATCH 84로 높아, 초기 단계 일부도 레이어에 없다.
- 결론: 이 레이어만으로는 1,190건 전체 경계를 얻을 수 없다. 완료 사업의 경계가 필요한지(투자자에게 중요한지)를 먼저 정해야 한다.

## 6. 공식 데이터와 지도의 사업 유형 불일치 (별도 보고)
선택된 공식 레코드가 있는 287건 중 **불일치 14건**(EXACT 3, PROBABLE 11). 유형 교차표(ZIP:ON 유형 | 공식 분류 → 건수): 재건축|재건축 98, 재개발|재개발 65, 신통|신통 28, 재개발|재정비촉진구역 27, 재건축|신속통합 25, 재건축|소규모재건축 21, 재개발|신속통합 4, 신통|재개발 4.
- EXACT 3건(자동 후보에서 제외, 사람 검토): 
  - `천호2구역 주택재건축정비사업조합` ↔ 공식 `천호2구역`(분류: **존치관리구역**) — DB는 재건축
  - `신이문2 역세권 도시정비형 재개발정비사업` ↔ 공식 `신이문2역세권`(분류: **장기전세주택**) — 도시정비형 재개발과 병행일 수 있어 오탐 가능
  - `수유동 310-15` (DB: **신속통합**) ↔ 공식 `(가칭)수유동 310-15번지 일대 가로주택정비사업`(**가로주택정비**) — 같은 필지의 다른 사업 유형으로 보임
- PROBABLE 11건은 대부분 이름이 부분만 겹친 다른 사업(예: `사당3 재건축` ↔ `두산위브(사당)`(미리내집), `덕수연립 재건축` ↔ `덕수연립 가로주택`)이다.
- 재건축|신속통합 25건은 불일치가 아니라 같은 사업이 신통 분류 행으로도 등록된 경우로 본다(프로그램 vs 방식).

## 7. 한계
- 위치 검사는 DB의 대표좌표(849건)가 있는 건에만 적용된다. 좌표 없는 EXACT 56건은 위치 검증이 없다.
- 대표좌표는 대표점일 뿐 구역 경계가 아니다. 위치 검사는 보조 증거이고 동일성을 정하지 않는다.
- 정확도(precision) 추정은 위치 검사 일치율(97~99%)이며 사람이 라벨링한 정답 대비 정확도가 아니다. 반영 전 표본 검수(예: 자동 후보 30건 지도 대조)가 필요하다.
