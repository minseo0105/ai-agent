## 1. AI 호출 보호 장치 설계

AI LAB(`ailab` 컨테이너)과 머니온(`moneyon` 컨테이너)은 프로세스가 따로라 **각자 같은 규칙의 문지기(gate)** 를 둔다.
공통 모듈: `services/ai_gate.py`(AI LAB), `apps/moneyon/services/ai_gate.py`(같은 코드 복사). 저장은 각 앱의 기존 볼륨 파일.

| 장치 | AI LAB | MONEY:ON | 동작 |
|---|---|---|---|
| **동시 호출 상한** | 6 | 8 | `asyncio.Semaphore`. 꽉 차면 대기열로 |
| **대기열 + 표시** | 최대 20명, 대기 10초 | 최대 30명, 대기 6초 | SSE 첫 이벤트 `queue {position}` → 화면 "순서대로 쓰고 있어요 · 앞에 N명"(꿀벌/에이전트 아이콘 애니메이션). 대기 시간 초과 → 준비된 결과 |
| **1인당 횟수** | 브라우저 세션 ID(로컬 무작위, `X-Ailab-Session`) 기준 대화 10회/10분 | 체험 토큰 기준 기능별 3회/10분, 합계 12회/시간 | 초과 시 "조금 뒤에 다시 눌러 주세요"(준비된 결과는 보여 줌). **IP 기준으로 막지 않는다** — 강의장 Wi-Fi는 30명이 같은 IP일 수 있음. IP는 느슨한 안전망(시간당 300회)만 |
| **하루 비용 상한** | `AILAB_AI_DAILY_USD=10` | `MONEYON_AI_DAILY_USD=3` | 호출마다 실제 `usage`(입력·출력 토큰)×단가를 날짜별 파일에 누적. 상한 도달 → AI 버튼은 즉시 준비된 결과 + "오늘 AI 사용량을 다 써서 준비된 답으로 보여 드려요". 관리자 화면에 오늘 사용액 표시. 이중 안전망: Anthropic Console 워크스페이스 지출 한도 |
| **시간 초과 대체** | 첫 이벤트 8초(도구 진행 표시 포함), 전체 45초 | 첫 글자 4초, 전체 15초 | 시간 안에 못 끝나면 끊고 준비된 결과로(머니온: 미리 생성한 AI 결과 → 규칙 문장, 에이전트: "지금 질문이 많아요" + 예시 답 1개) |
| **오류·거절** | 같은 처리 | 같은 처리 | `refusal`·`max_tokens`·HTTP 오류·금지 표현 검사 실패 → 대체. 관리자 화면 'AI 상태'(STOCK:ON에 있는 것과 같은 방식)에 실패 횟수·마지막 오류 |

- Anthropic 조직 등급의 분당 요청·토큰 한도를 Console에서 확인한다(11/3). 동시 14개(6+8) × 짧은 출력이면 일반 등급 한도 안이지만, 시연 30분 동안의 분당 출력 토큰을 부하 테스트(4절)에서 실제로 잰다.
- STOCK:ON은 방문자 요청이 AI를 부르지 않으므로 이 장치가 필요 없다(스케줄러 호출만, 하루 약 $0.2).

## 2. MONEY:ON 사람별 데이터 분리·동시 저장 (코드 확인 결과)

| 항목 | 확인한 사실 | 판정 |
|---|---|---|
| 사람별 분리 | 체험 시작 때 32바이트 무작위 토큰 발급, DB에는 SHA-256만. 모든 요청은 `X-Moneyon-Trial` 헤더 토큰으로 **자기 체험 통장만** 조회·기록(`resolve`가 토큰·아이 ID를 함께 확인, 다르면 403) | 안전 |
| 브라우저 보관 | `sessionStorage`(탭 단위). 같은 휴대폰 두 탭 = 서로 다른 체험. 카카오톡 인앱 브라우저도 동일 | 안전(탭을 닫으면 새 체험) |
| 체험 통장 수 | 미리 만든 통장 120개(`MONEYON_TRIAL_POOL=120`), 시연 1.5배(45명)보다 충분. 24시간 만료, 보관 상한 3,000 | 충분 |
| 동시 기록 | 프로세스 1개 + SQLite WAL, 쓰기는 프로세스 잠금으로 **순서대로**(잠금 대기 최대 30초), 같은 요청 두 번 누름은 `request_key` 고유키로 한 번만 반영 | 안전(느려질 수는 있음 → 부하 테스트로 시간 확인) |
| 혼잡 시 | SQLite 잠금 실패 → 503 "지금 체험하는 사람이 많아요" + `Retry-After: 5` | 화면이 자동 재시도하는지 11/3 확인, 없으면 1회 자동 재시도 추가 |
| 시연 모드 | 시연 데이터를 **각자 체험 통장에 복사**해 채우는 방식(공유 통장 아님) | 섞이지 않음 |

부하 테스트에서 "섞임 0건"을 직접 확인한다: 가상 사용자마다 고유 금액(예: 100원×사용자 번호)을 기록하고, 끝에 각자의 기록 목록에 자기 금액만 있는지 검사.

## 3. 자유 입력 제한·차단

원칙: **AI에는 자유 문장을 보내지 않는다.** 숫자·카테고리·날짜만 보낸다(MONEYON_AI_PLAN.md).

| 입력 | 지금 | 시연 전 |
|---|---|---|
| 목표 저축 코치 | (새 기능) | 목표는 **저축통장에서 고르기**(목표 금액은 프리셋 버튼 + 1,000~1,000,000원), 주당 저금액은 **슬라이더**(100원 단위). 자유 문장 입력 없음 |
| 저축통장 이름·별명 | 30자·20자 자유 입력 | 이름 20자로 줄이고 아래 차단 적용, AI에는 안 보냄(화면 표시만) |
| 쓴 곳 메모(`note`) | 자유 입력 | 20자 제한 + 차단 적용, AI에는 안 보냄 |
| AI LAB 에이전트 대화 | 메시지당 8,000자 | 시연 기간 500자, 대화 20턴. 아래 차단 적용 |

차단 규칙(서버에서 검사, 화면에도 같은 안내): 욕설·비하 표현 목록, 전화번호·이메일·주민번호·계좌번호 모양(숫자 패턴), URL, 제어문자·이모지 과다(같은 글자 10번 이상 반복). 걸리면 저장하지 않고 "이 말은 쓸 수 없어요"만 보여 준다(무엇이 걸렸는지 자세히 쓰지 않음). 공통 함수 `input_guard.check(text, max_len)` + 테스트.

| 주소 | **짧은 도메인 연결 권장**(예: `ailab-demo.kr` 같은 것, 연 2만 원 안팎). 지금 `140-245-88-198.sslip.io`는 길고, 일부 회사 Wi-Fi·보안 필터가 동적 DNS 주소를 막을 수 있다. 도메인 A레코드 → `140.245.88.198`, 서버 `.env`의 `SITE_ADDRESS` 변경 → Caddy가 인증서 자동 발급. sslip.io 주소는 예비로 그대로 동작 |

| QR 코드 | 시연 첫 화면 주소 1개(예: `https://도메인/demo` — AI LAB·STOCK:ON·MONEY:ON 큰 버튼 3개짜리 안내 페이지)를 QR로. 오류 정정 H, 슬라이드에 크게 + 인쇄물. QR 아래 짧은 주소도 글자로 |
