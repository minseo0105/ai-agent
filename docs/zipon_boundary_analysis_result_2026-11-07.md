# ZIP:ON 개발구역 경계 매칭 분석 결과 (읽기 전용, 2026-11-06 예약 실행)

**운영 DB는 SELECT만 했다**(`development_projects`, 10개 컬럼, 읽기 전용 트랜잭션, 서비스 역할 키 미사용). DB 쓰기·배포·GeoJSON 생성 없음.
SHP 202609판은 공공누리 4유형(출처표시·상업적 이용금지·변경금지)이므로 **이 문서는 집계 수치만** 담고, 경계·폴리곤·행 단위 결과는 저장소에 두지 않았다.
SHP 데이터의 서비스 적용·가공 데이터 배포·운영 DB 저장은 보류 상태다.

## 1. 레이어 분석 (UPIS_C_UQ120, 202609판)
- 2,776 레코드(Polygon 2,684 + MultiPolygon 92), EPSG:5174, 25개 자치구, 생성일 2025-12-31 ~ 2026-09-04, 사업명 중복 70건. 속성 인코딩 cp949.
- **서울플랜+ 전체 도시계획사업 현황 카탈로그**다(정비 외 사업 포함). 사업 분류(`SCLAS_CL`, 코드정의표로 해석)별 레코드:

| 분류 | 레코드 |
| --- | ---: |
| 가로주택정비 | 720 |
| **재개발**(주택정비형·도시정비형) | **297** |
| **신속통합기획** | **231** |
| **재정비촉진구역** | 213 |
| **재건축**(단독·공동) | **198** |
| 미리내집 143 / 청년안심주택 136 / 모아타운 107 / 소규모재건축 105 / 리모델링활성화 76 / 자율주택 76 / 장기전세 70 … | |

- **재개발·재건축 포함 여부: 포함된다**(재개발 297, 재건축 198, 신속통합 231, 재정비촉진구역 213). 다만 "현황" 데이터라 **완료·해제·과거 사업이 빠졌을 가능성**이 있다(아래 NO_MATCH 원인 참조, 단계 정보는 조회하지 않아 확인하지 못했다).
- 사업 코드 `PROPEL_CD`는 추진단계 코드(예: PP0206 조합설립인가, PP0208 사업시행인가, PP0209 관리처분계획인가)로 코드정의표에서 해석된다. `PRESENT_SN`은 서울시 사업 식별번호 `cleanup` 별칭과 대응이 확인되지 않아 동일성 키로 쓰지 않았다.
- 경계 정확도 주의: "법적 효력 없음 / 참고자료".

## 3. 정확도 검증 (이름 매칭과 독립된 위치 검사)
- EXACT 152건(좌표 보유) 중 **150건(98.7%)은 대표좌표가 매칭된 폴리곤 안**, 2건은 밖. 밖의 사례: `장위 4구역 주택재개발정비사업조합`(좌표가 `장위2구역` 폴리곤 안, 이름 `장위4구역`과 불일치), `정릉7 주택재건축정비사업 조합`(좌표가 어떤 폴리곤에도 없음). 둘 다 자동 반영 후보에서 제외됐고, 이런 건이 "이름은 맞는데 위치가 틀린" 오매칭 위험의 실례다.
- 좌표 보유 849건 중 NO_MATCH 479건: **260건은 좌표가 같은 자치구의 어떤 폴리곤 안**에 있고(이름이 달라 못 맞춤), 219건은 어떤 폴리곤에도 없다.
  - 위치만으로 찾은 후보는 **동일성 증거가 아니다**(이웃 사업·상가시장·청년안심주택 등 다른 사업일 수 있음). 이름 불일치 사례: `한림연립주택재건축조합` ↔ `면목 패션특구`(도시재생), `용답동 15` ↔ `용답상가시장 일대` — 이런 건은 자동 채택하면 오매칭이다.

## 4. 미매칭·검토의 원인과 개선 여지 (분석 시뮬레이션, 코드·규칙은 변경하지 않음)
1. **표기 차이(NO_MATCH):** `미아제3구역` ↔ `미아3`, `청파제1구역` ↔ `청파1구역`, `양평제12구역`, 앞의 `69.`·`(가칭)`·`(임시)`, `○○동 153-19번지 일대 … 재개발사업` ↔ `개봉동153-19`. 보강 규칙(제N구역→N, 번호 접두·가칭 제거, 번지 일대 꼬리 제거)을 얹어 시뮬레이션하면 **EXACT 201 → 227(+26)**, NO_MATCH 605 → 546. 위치 검사는 **170/173(98.3%)로 정밀도 유지**. 규칙 보강은 코드 변경이므로 별도 승인 후 테스트와 함께 진행해야 한다.
2. **레이어 중복 행(AMBIGUOUS 340 중 195):** 같은 사업이 신속통합·재개발/재건축·재정비촉진구역 분류로 **여러 행**으로 들어 있다(예: `상록수아파트` BZ101+BZ105, `마천2` BZ402+BZ103+BZ101). 이름이 같은 후보 195건 중 **176건은 후보 도형 간 IoU ≥ 0.9**(사실상 같은 도형), 12건 0.5~0.9, 7건 <0.5. IoU ≥ 0.9인 중복을 "한 사업의 중복 행"으로 묶으면 최대 +176건이 후보가 된다(근거 레코드 ID를 모두 보존하고 사람 검토 후에만).
3. **ZIP:ON 내부 이름 충돌 80건**(같은 정규화명의 사업이 둘 이상) — 사업 쪽 중복 정리와 연결(검토 대기 159건과 겹침).
4. **구조적 NO_MATCH:** 위 보강을 해도 약 45%는 남을 것으로 보인다. 원인은 이 레이어가 "현황" 카탈로그라 오래된·완료 사업이 없거나, 이름이 크게 다른 경우로 추정되나 **단계(stage) 컬럼을 조회하지 않아 확인하지 못했다**(승인된 컬럼 범위 밖).
- 이름 규칙 보강 + 중복 행 처리를 모두 적용했을 때의 **이론적 상한은 약 400건(34%)**이다(201+26+176, 위치 검증 후 감소). 이 숫자는 추정이다.

## 5. 라이선스 제약
- 이용허락: 공공누리 4유형(**출처표시 + 상업적 이용금지 + 변경금지**). 좌표 변환(5174→4326)·사업 데이터와의 결합이 "변경"에 해당하는지, ZIP:ON이 "상업적 이용"인지가 미해결.
- 따라서 **서비스 적용, 가공 데이터 배포, 운영 DB 저장 보류**. 질문 8개와 문의 경로: `docs/zipon_shp_license_inquiry_2026-11-06.md`.
- 대안 데이터(국가공간정보포털 정비구역, 서울도시공간포털 정비사업구역계)의 이용조건은 미확인.

## 6. 실거래 API 데이터 품질
- **분석하지 못했다.** 이 환경에 `PUBLIC_DATA_API_KEY`가 없고(`--check-config`: false), 입력 폼 방식(Bearer)은 공공데이터포털 게이트웨이가 헤더를 읽지 않아 인증되지 않는다(가짜 키 실험으로 확인). 결과를 만들지 않았다.
- 필요한 입력: 키가 있는 로컬에서 `python scripts/sample_molit_trade_apis.py --lawd 11710 --lawd 11140 --ymd 202610 --out molit_sample.json` 실행 후 JSON 공유(키·원자료 행 미포함, 필드 채움률·지번 공개율·취소 분포만 포함). 호출 한도는 포털 마이페이지에서 확인.
- 이미 확인된 사실: 응답에서 쓰는 위치 단서는 법정동명·지번·도로명이며 좌표는 없다. 분양권·입주권 API(`RTMSDataSvcSilvTrade`)의 필드는 **미확인**.

## 8. 추가 승인이 필요한 항목
