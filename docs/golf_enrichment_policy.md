# 골프 DB 보강·자동 갱신 정책

## 적용 범위와 호환성

기존 원장 레코드·ID·검색 Pool·화면 필드는 유지한다. phone, pricing.fee_records, operations의 팀당 비용, 안내용 placeholder인 course_overview만 검증 후 채운다. 실질적인 기존 값은 자동 덮어쓰지 않는다.

추가 메타데이터는 field_evidence(필드별 출처/근거/확인일), enrichment.history(이전 값과 근거), enrichment.candidates(조건부·충돌·미검증 후보), enrichment.approved_source_urls(지점 식별까지 검토한 정확한 페이지), enrichment.facts(검증된 시설 특성)다. 기존 JSON 소비자는 모르는 키를 무시하므로 DB 전체 구조나 기존 필드 타입을 바꾸지 않는다. 사실·후기 데이터를 섞지 않는다. 시설 특성은 현재 검색 필터를 자동 활성화하지 않는다.

## 수집과 반영

- 공식 홈페이지 안의 요금·월별 공지·안내 페이지를 수집한다. 같은 co.kr이라는 이유로 다른 사이트 링크를 따라가지 않는다.
- 본문은 원문 URL과 함께 수집 결과에 보존한다. 자동 반영은 최근 7일 이내 관찰, 사전 검토된 정확한 지점 페이지, 해당 페이지에 실제 있는 인용, 금액/범위 검증을 요구한다.
- 처음 보는 사이트·페이지, 본문과 대조할 수 없는 이미지, 고객 구분이 불명확한 요금, 날짜·시간·이벤트·캐디 유형 조건은 검토 후보다. 수집 성공이 곧 반영 성공은 아니다.
- 사람이 확인한 연구 결과는 review_method=human_official_source, 필드별 reviewed=true와 관찰일을 명시한다. 이 값은 추출 모델이 생성하는 필드가 아니다. 근거가 원문 인용인지 요약인지도 구분한다.
- 기존 값과 다르면, 과거 자동 수집값이라도 충돌 후보로 보존한다. --refresh는 새로 관찰한 동일 값의 확인일/근거를 재확인하는 옵션이다.
- 캐디 방식·2인·3인·야간은 조건 해석 오류가 추천에 직접 영향을 주므로 기본적으로 후보에 보존한다. 기존 --apply-players 인수는 호환을 위해 받지만 자동 필터 반영을 허용하지 않는다.
- 저장 전 백업하고 임시 파일을 원자적으로 교체한다. 중복 ID나 수집 중 DB 변경은 중단한다. --dry-run은 DB를 수정하지 않는다.

## 갱신 일정과 최신성

기존 golf-quarterly-refresh.yml 및 실행 스크립트 이름은 호환용으로 유지한다.

- 1·7월: 공식 URL을 가진 추천 대상 전체 수집.
- 4·10월: 검토된 가격 출처가 있는 곳만 --prices-only 재확인. 요금 갱신은 전체 조사와 합쳐 분기별이다.
- 예정 시각: 한국시간 1·4·7·10월 2일 03:00. 자동 실행 시작일 2026-10-01 UTC.
- 새로 보강한 일반 요금은 확인 후 최대 90일을 유효 확인 기간으로 둔다. 실제 종료일이 더 빠르면 그 날짜를 쓴다. 이는 가격 보장 기간이 아니라 재검증 정책이다.
- 기한 지난 그린피는 상세정보의 과거 자료로 남지만 예산 필터에 사용하지 않는다. 새 팀당 비용도 fresh_until이 지나면 예상비용 계산에 사용하지 않는다.
- 월별 이벤트 가격은 기간·시간대를 보존한 후보이며 무조건적 현재 가격으로 승격하지 않는다.
- 실행 보고서와 백업은 GitHub Actions artifact로 30일 보관한다. 후보와 출처는 DB 및 수집 보고서에 남는다.

로컬 워크플로 파일을 고친 것만으로 원격 예약이 활성화되지는 않는다. 저장소 기본 브랜치 반영, Actions 활성화, ANTHROPIC_API_KEY Secret, API 크레딧이 필요하다. 이번 작업에서는 유료 LLM 전수 수집을 실행하거나 원격에 push하지 않았다. 기존 수집기의 모델 이름 및 의존성 조합을 사용하므로 실제 API 호출 가능 여부는 첫 수동 dry-run에서 확인해야 한다.

## 골프장 특징과 후기

1. 벙커 수·페어웨이 폭: 공식 제원/코스 자료에 명시되어 있을 때만 수치 사실로 저장한다. 홀 단위 자료를 골프장 전체로 확대하지 않는다. 벙커 53개 같은 사실과 '벙커가 많다'는 비교 평가는 다르다.
2. 공식 코스 설명: 출처의 설명임을 표시한다. '넓은 페어웨이'라는 홍보 문구를 측정 폭으로 바꾸지 않는다.
3. 시설 존재/규격: 연습장 타석 수, 길이, 휴무일처럼 검증 가능한 사실을 조건과 함께 기록한다.
4. 시설 품질·관리·친절도: 독립적인 최근 후기의 평가다. 객관적 사실로 자동 덮어쓰지 않는다. 작성일·방문일(알 수 있으면)·출처 URL·작성자 중복 제거·대상 코스·광고 여부·긍정/부정 근거를 함께 관리해야 한다. 부족하면 '후기 부족'을 유지한다.

이번에는 후기를 새로 수집하거나 평점을 생성하지 않았다. 기존 후기 분석 기능을 삭제하지 않았으며 새 사실 보강기는 review_runtime.json과 기존 평가를 수정하지 않는다. 기존 golf_expressions.py에는 특정 골프장에 맞춘 규칙이 있어 그대로 전체 골프장 자동 평가기로 사용해서는 안 된다. 범용 후기 자동 갱신은 별도 대상 식별·독립 표본·최신성 검증 후 연결해야 한다.

## 운영 명령

프로젝트 루트에서 환경에 맞는 Python으로 실행한다.

```text
python scripts/apply_golf_review.py data/golf/enrichment_review/reviewed_2026-09-24.json --dry-run
python scripts/golf_quarterly_refresh.py --limit 2 --dry-run
python scripts/golf_quarterly_refresh.py --prices-only --dry-run
python -m unittest discover -s tests -p test_golf_import_policy.py -v
```

전화번호 일괄 감사 스크립트 golf_phone_audit.py는 후보만 만든다. 본사 번호/팩스/다른 지점/구명칭 혼입을 방지하기 위해 곧바로 DB에 쓰지 않는다.
