# STOCK:ON 계획 (AI LAB 증권 섹션)

## 뉴스 속 숨은 종목 — 핵심 목적 (모든 판단의 기준, 2026-10-30)

STOCK:ON의 핵심은 **'일상 뉴스를 보다가 → 그 뉴스와 연결된 상장사를 AI가 찾아내는 것'** 이다.
뉴스 자체는 종목 이야기가 아니어도 되고, 오히려 일상 뉴스에서 '이 회사가 연결돼 있었네' 하고 발견하는 것이 재미이자 차별점이다.

### 이슈 고르는 기준

- **고를 뉴스**: 일상 뉴스면에 나오는 사건·변화 — 보안 사고, 제품 결함·리콜, 유가·환율 변화, 정책·규제, 국제 정세, 날씨·질병, 생활·소비 트렌드, 기술 발표 등. 여러 언론이 다룬(기사 수) 오늘의 이슈 중 산업·기업에 영향이 있을 만한 것.
- **제외할 뉴스**: 기업 실적 발표·공시, 특징주·관련주·급등 기사, 증시 시황·지수 기사처럼 처음부터 종목이 주인공인 증권 기사. 이슈로 쓰지 않고, 연결된 회사의 '왜 움직였나' 설명이나 '오늘 시장 분위기' 띠에만 활용한다(코드: `lifemap.STOCK_RULES`, 빠진 기사 예시는 `lifemap_status.json`의 `excluded_examples`).
- 이슈 3~5개, 서로 다른 분야.
- 이슈 지도 중심은 뉴스의 핵심 사건 그대로(예: '금융권 해킹', '아이폰 듀오 결함'). 기사 요약에 한 번 나온 부수 주제를 중심으로 삼지 않는다(대표 기사 제목과 두 제목 이상에 이슈 이름의 말이 있어야 통과, `centered`).
- 거시 이슈(금리·환율·지수 전반)는 최대 1개, '시장 전체 영향 이슈' 배지. AI 해석 첫 줄에 시장 예상과 같았는지/달랐는지, 같았으면 '예상대로' 배지. 연결 회사의 연관도는 '약'으로 고정하고, 그 회사 고유의 직접 연결이 기사에 나올 때만 '중' 이상.
- 유가·환율·금리처럼 오르내리는 이슈는 오늘 실제 방향(상승/하락/보합)을 먼저 판단해 카드에 표시("오늘 유가: 하락")하고 회사별 긍정/부정도 그 방향 기준. 판단이 어려우면 '방향 불확실' + '영향 가능'만.
- 시점: 첫 보도가 15:20 이후(또는 휴장일)면 다음 거래일 등락과 비교하고 '장 마감 후 뉴스 · 다음 거래일 반응을 보여드려요', 그 거래일 값이 아직 없으면 '반응 대기 중'. 첫 보도 이후 누적 시장 대비(최대 5거래일)는 회사 상세·표에만.
- 숫자: '시장보다 = 그 회사 주가 등락 − 시장 지수 등락'. ±2%p 이내는 '시장과 비슷해요'(회색, 반대 움직임 아님), '실제 등락 큼'은 ±3%p 이상. 화면에 '단순'이라는 말을 쓰지 않는다.

#### 2026-10-30 개편: 출처·오늘 우선·중복 금지·이름·숨은 연결

- **출처(역할 분담)**: '오늘 무슨 일이 있었나'(이슈 발견)는 종합 언론사·방송사 일상 뉴스면 RSS — 연합뉴스(사회·국제·문화·건강)·SBS(사회·국제·생활문화·IT과학)·JTBC(사회·국제·문화)·경향(사회·문화·과학)·동아(사회·국제·문화·과학)·조선(사회·국제·문화). 경제·증권 섹션은 넣지 않는다. MBC·KBS는 서버에서 오류 페이지로 넘어가고, 한겨레는 발행 시각이 없어 뺐다(2026-10-30 서버 확인). '얼마나 많이 다뤘나'(최근 24시간 기사 수·언론사 수)·관련 기사·첫 보도는 NAVER 뉴스 검색. 목록은 설정 파일 `data/stockon/news_sources.json`(rss·general_press)에서 바꾼다.
- **대표 기사**는 종합지·방송사(RSS) 기사. 경제지·전문지 기사는 '관련 기사'에만.
- **고르기**: Haiku가 같은 사건 기사를 묶고 '산업·기업과 이어지는 이슈'(linked)만 후보로(최대 9개, 통과가 3개 미만이면 한 번 더 묻는다). 언론사 2곳 이상이 다룬 것만. 첫 보도가 최근 24시간 안인 이슈를 언론사·기사 수 순으로 먼저, 더 오래된 이슈는 최대 1개 '계속되는 이슈' 배지. 기준 창 안 RSS 기사가 20건 미만(예전 기준일)이면 예전 방식(NAVER 검색어).
- **중복 금지**: 사건 종류(kind: 해킹·정보유출·제품 결함·리콜·산업 사고·화재 등 16가지)가 같으면 분야 이름이 달라도 하나만. 실적·공시·특징주·시황 기사는 이슈로 쓰지 않고, 거시 이슈 최대 1개(기존 규칙 유지).
- **이름과 말투**: 분야 이름(label)은 업종명이 아니라 일상 말('개인정보 유출'·'전기차 리콜'·'스마트폰 결함'·'은행 해킹'). 카드 제목·요약에 종목명·주가·급등·증시 같은 증권 표현을 쓰지 않는다(`CARD_BANNED`). AI 해석은 일반인 말로, '이 뉴스가 어떤 회사들과 어떻게 이어지는지' 2~3줄, 해석 과정·자료 상태에 대한 말은 쓰지 않는다.
- **숨은 연결**: 기사에 이름이 나온 상장사(또는 비상장 당사자의 지분을 가진 상장 모회사)는 '뉴스 당사자'(최대 2). 나머지는 기사에 이름이 없는 근거 있는 연결 — 1차(공급사·고객사·사고 대응·규제 대상), 2차(경쟁사·대체재·같은 업종). 회사마다 연결 근거 한 줄·KRX 업종·근거 기사. 이슈당 최대 6곳(넘치면 2차·약한 연관부터 뺀다). 기사 밖 연결이 2곳 미만이면 한 번 다시 묻는다. 당사자가 비상장이고 지분 관계를 모르면 넣지 않는다.
- **한 줄 회사 소개**는 Haiku가 회사별로 한 번 만들어 `lifemap_intros.json`에 저장·재사용(권유·주가 표현이면 버린다).
- **관련 업종 오늘**: 회사 업종을 '오늘 시장' 탭과 같은 키움 업종 등락(`market_extra.json`)으로 시장 대비 %p, 최대 4개. 업종이 '모름'이거나 같은 날 지수가 없으면 칩을 뺀다. 화면은 `/api/stock/lifemap/pulse`로 15초마다 숫자만 갱신(AI 재호출 없음). KRX 업종에는 '보안'·'은행'이 없어서 'IT 서비스'·'금융'처럼 실제 업종 이름으로 보인다.

#### 2026-10-30 저녁: 이슈 생성 보완(0단계)과 기업 연관성 검증(verify.py)

목표: 뉴스에 나온 단어나 업종이 비슷하다는 이유만으로 회사를 잇는 오탐을 막는다. 코드 `services/stockon/verify.py`, 별칭·비상장·해외 목록 `data/stockon/company_aliases.json`, 테스트 `tests/test_stockon_verify.py`(고정 사례 `tests/fixtures/stockon_verify_cases.json`).

- **같은 사건 합치기**(`lifemap.same_event`): 기사 주소가 겹치거나, 사건 말(이슈 이름·검색어·분야 이름, 흔한 말 제외)이 둘 이상 겹치거나, 하나 겹치고 당사자가 같거나 제목 말이 3개 이상 겹치면 같은 사건 → 하나로 합치고 첫 보도는 더 이른 쪽. 새 후보끼리, 완화 단계 후보, **같은 기준에서 유지하던 이슈**, 화면 후보(다음 후보·섹터)에 모두 적용. 버린 수는 상태 `rejects.same_event`.
- **이슈가 3개 미만일 때 단계적 완화**(상태·`lifemap.json`의 `relax`에 기록): ① `naver_general` NAVER 이슈 검색어로 찾은 **종합지·방송사** 기사(24시간 안)도 후보로 ② `ongoing48` 첫 보도가 24~48시간인 이슈를 '계속되는 이슈'로 최대 2개 ③ `short` 그래도 부족하면 그대로 둔다(예시·다른 이슈로 억지로 채우지 않는다. 화면도 만든 수만큼, 오늘 이슈가 하나도 없을 때만 예시). 단계별 후보 수는 상태 `funnel`(RSS 창 안·사용·증권 기사 제외·AI 후보·통과·회사 없음·만든 수).
- **당사자**: 기사 제목·요약에 이름이 실제로 나온 회사만. 상장 여부는 AI가 아니라 종목 목록·별칭 파일로 정한다(예: 삼성SDS→삼성에스디에스). 모회사·지주사 연결(국민은행→KB금융 등)은 별칭 파일에 근거 문구(source)가 있을 때만, 등급 '확인됨'. 비상장·해외 당사자는 화면에 '(국내 비상장)'·'(해외)'로 표시(최대 3, 사람·언론사·정부·단체 제외). 국내 상장사와의 연결은 아래 검증을 통과할 때만.
- **근거 출처(이것만)**: DART 공시(기존 키 — 단일판매·공급계약 공시 원문, 공급망을 주장한 회사는 최근 사업보고서 원문에서 당사자 이름이 나온 문장, 원문은 수집기 볼륨 `verify_cache.sqlite`에 압축 캐시), NAVER 뉴스 검색(제목·요약·링크), 이슈의 언론사 RSS 요약. 언론사 본문은 가져오지 않는다. 근거마다 출처 URL·종류(공시/뉴스/RSS/공식자료)·발행 시각·확인 시각 저장.
- **시점**: 근거 발행 시각 ≤ 분석 기준 시각(이슈 기준 창 끝과 지금 중 이른 쪽). DART는 접수일만 있어 **기준일 전날까지** 접수된 공시만. 뒤에 나온 자료 수는 `verify.after_ref`.
- **AI 근거 문장 대조**: Sonnet 5.5가 회사마다 관계 종류(계약·공급망·지분·경쟁·사업 / 같은 업종 / 근거 없음), 자료 번호와 근거 문장, 영향 있음/없음, 영향 경로, 방향을 낸다. 코드가 ① 문장이 그 자료에 글자 그대로(띄어쓰기·문장부호 무시) 있거나 문장 말의 80% 이상이 있고 ② 자료에 회사 이름(공시는 그 회사가 낸 것)과 ③ 이 사건(당사자 이름, 또는 사건 말 2개 이상 — 업종 말 하나로는 안 됨)이 함께 나올 때만 근거로 인정. 자료가 '영향 없었다'(정상 운영 등)고 하면 연결이 아니라 업종 참고.
- **분류**: 직접 당사자 / 검증된 간접 영향(근거 통과) / 단순 업종 참고(AI 검증이 '같은 업종'이라 했거나, AI 해석이 원래 경쟁사·대체재·같은 업종이라 한 회사 — 지도에 올리지 않고 접힌 회색 줄에 등락만) / 근거 부족(공급·고객·사고 대응·규제·지분을 주장했는데 근거가 없음 — 화면에 안 보이고 `lifemap_verify_log.json`(최근 200건)에만). 근거 자료에서 AI가 새로 찾은 상장사(예: 사고 난 시스템의 공급사)는 근거를 통과하면 최대 2곳 추가.
- **증거 등급**(확률이 아님): **확인됨** = 공시·공식자료 / **보도 확인** = 서로 다른 언론사 2곳 이상 / **단일 보도** = 1곳 / **근거 부족**.
- **영향 방향**: 근거로 사업 영향 경로가 설명될 때만 긍정·부정·중립, 아니면 '영향 방향 불확실'. 경로 문장에 수혜·피해·오를·내릴·추천·매수·매도가 있으면 방향을 쓰지 않는다. 근거 없는 회사를 이름으로 말하는 AI 해석 문장은 뺀다.
- **이슈 선정**: 검증된 국내 상장기업(당사자·검증된 간접 영향)이 있는 이슈를 먼저, 없는 이슈는 최대 1개('검증된 국내 상장기업 없음' 배지, 지도 대신 안내). 완화 단계를 거쳐도 억지로 채우지 않는다.
- **설정·안전**: `LIFEMAP_VERIFY=1`(기본)/`0`. 끄거나 검증 중 오류·시간 초과(이슈당 150초)면 지금 방식 결과 그대로 + `verify.status`가 `off`/`unverified` → 화면 '검증 전' 배지(빈 화면 없음). 직접 입력 단어·예시 파일도 검증하지 않으므로 '검증 전'. Supabase 미사용.
- **화면**: 지도에는 당사자·검증된 간접 영향만. 목록 묶음 뉴스 당사자 → 검증된 간접 영향 → (접힌) 업종 참고. 회사를 누르면 증거 등급 배지·영향 방향·연결 이유·근거 자료(종류·언론사·발행 시각·링크·근거 문장)·확인 시각. 실시간 등락·시장 대비·관련 업종 칩·경로 태그·회사 소개는 그대로.
- **비용**: 검증 1회(이슈 하나) Sonnet 5.5 입력 약 8천·출력 약 0.3~0.5천 토큰 ≈ $0.02. NAVER 검색 이슈당 약 4~7회, DART 목록 회사당 1회 + 원문 최대 3건.

작성 2026-10-27, 같은 날 보강(모의 키 지원 확인·조회 전용 허용 목록·키 보관), **같은 날 방향 확정(아래 "운영 결정")**.

## 운영 결정 (2026-10-27, 사용자 확정)

- **성격 정정**: 회사 서비스가 아니라 **개인 프로젝트**. 아는 사람 몇 명만 로그인해서 무료로 보는 사이트.
- **키움 서면 답변을 기다리지 않고 모의 키로 2단계(장중판)까지 진행**한다. 키움 문의(6절)는 참고용으로 보낸다.
- 조건:
  - **로그인한 사용자만** 볼 수 있다(접근 관리 "등록된 사람만"). 광고·유료화 없음.

## 0. 조사 결론 (운영 결정 전 작성 — 결정은 위 "운영 결정"이 우선)

1. **키움 REST API 시세를 여러 사람에게 보여주는 것(재배포)은 공개 문서로는 "허용"이 확인되지 않는다.** (→ 개인 프로젝트·로그인 소수·무료·출처 표시 조건으로 진행하기로 사용자가 결정. 키움 문의는 참고용)
   - 키움 공개 문서(`openapi.kiwoom.com`)에는 재배포·제3자 제공 조항이 **없고**, 적용 약관인 「오픈 API 서비스 이용약관」 본문은 공개 웹에서 열람되지 않았다(목록에만 있음).
   - 서비스 자체가 "당사 계좌를 보유하고 HTS ID를 연결한 고객"용 = **개인 계좌에 묶인 개인 이용 서비스**다.
   - 업계 기준(한국투자증권 KIS Developers): 제3자에게 서비스를 제공하려면 제휴가 필요하고 제휴 대상은 투자일임·자문업 등 제도권 금융회사뿐이며, **"KRX 및 해외거래소 시세정보를 이용하려는 경우 KRX 또는 해외거래소와 정보이용계약이 필요"**, 계약 없이는 **"API를 이용해서 … 화면으로 시세정보를 이용하는 것도 불가"**라고 거래소(코스콤) 통보를 공지했다. 키움도 같은 거래소 시세를 받으므로 같은 제약이 걸릴 가능성이 높다.
   - → **키움 실시간·장중 시세는 키움의 서면 확인(필요하면 KRX/코스콤 정보이용계약) 전에는 화면에 쓰지 않는다.** 아래 6절의 질문으로 키움에 확인.
2. **대안(바로 가능): 공공데이터 시세(전일 기준) + DART 공시 + 뉴스 + AI 요약**으로 1단계를 만든다.
   - 금융위원회_주식시세정보·지수시세정보: 무료, **기준일 다음 영업일 13시 이후 갱신(T+1)**, 이용허락 **공공누리 제4유형(출처표시·상업적 이용금지·변경금지)** → 내부 비상업 이용·출처 표시 조건. "변경금지" 해석(정렬·등락률 계산·히트맵 표현이 '변경'인지)은 담당 부서 확인 권장.
   - 외국인·기관 동향은 공공 API에 없음 → 1단계에서는 빼거나 "키움 확인 후" 표시.
3. **모의투자 키로 필요한 데이터를 부를 수 있다(공식 스펙 기준) → 모의 키를 기본으로 계획한다.**
   - 키움 공식 GitHub의 API 스펙(`kiwoom/_data/kiwoom_api_spec.json`, 337개)에서 STOCK:ON이 쓸 TR **전부**(지수 `ka20001`·`ka20009`, 순위 `ka10027`·`ka10032`·`ka10030`, 투자자 `ka90009`·`ka10051`·`ka10008`·`ka10131`, 종목 `ka10001`·`ka10095`·`ka10099`·`ka10101`, 토큰 `au10001`)에 **"모의투자 도메인 https://mockapi.kiwoom.com"**이 적혀 있다. 공식 Postman 컬렉션도 HTTP API 306개를 PRD/MOCK 양쪽으로 제공한다.
   - 스펙 전체에서 "해당 API는 모의투자를 지원하지 않습니다"라고 적힌 것은 **계좌 TR `ka01690`(일별잔고수익률) 하나뿐**이다. STOCK:ON과 무관.
   - 남는 확인점(공식 문서에 없음): ① 모의 서버 응답이 **실제 KRX 시세와 같은 값**인지(지연 여부 포함) ② 모의 키만 쓰면 자동 해지되는지 — 공식 안내 "접속 기준은 '실서버'로 모의투자 서버로만 로그인하신 경우 서비스가 자동 해지될 수 있습니다". 둘 다 키움 문의(6절)로 확인하고, ①은 사용 승인 후 며칠간 공공 T+1 종가와 대조해 검증.
   - 제약: 모의 서버는 **KRX만**(NXT 대체거래소 시세 없음 → 화면은 "KRX 기준"), 한도 **TR 1개당 1초 1회**. 5분 주기 수집에는 충분(3-2절).
   - 모의 키를 쓰더라도 시세의 원천은 KRX이므로 **재배포 문제(1번)는 똑같이 남는다.**
4. **실전 키를 쓰게 되더라도 조회만 하게 만든다**: 코드 안에 조회 TR 허용 목록(api-id ↔ URL 고정)만 두고, 주문·계좌·실시간(WebSocket) API는 **코드에 아예 넣지 않는다**(3-6절).
5. **키와 토큰은 수집기 컨테이너 안에서만** 쓴다. AI LAB 웹 컨테이너·브라우저·HF Space·로그·스냅샷 어디에도 내려가지 않는다(3-6절).
6. 서버 구조: **수집기(collector) 컨테이너가 정해진 주기로 모아 저장 → AI LAB API는 저장된 스냅샷만 읽음.** 사용자 요청이 키움·공공 API를 직접 부르지 않으므로 사람 수와 무관하게 호출량이 고정된다.

## 3. 수집·캐시 구조

### 3-1. 구성

```
[stockon-collector 컨테이너]  ──(키움·공공·DART·뉴스·LLM, 주기 호출)──▶  스냅샷 저장(볼륨 stockon-data, SQLite + JSON)
          │                                                               ▲ 읽기 전용
          └ 키는 .env.stockon (수집기에만)                                │
[ailab 컨테이너]  /api/stock/*  ── 스냅샷만 읽어 응답 ──▶ 브라우저(구성원)
```

- 수집기는 **AI LAB 이미지를 재사용**하고 `command`만 다르게(`python -m services.stockon_collector`). 단일 프로세스·단일 토큰(키움은 토큰당 세션 1개).
- 키움 키는 `.env.stockon`(600)에만 두고 **ailab 컨테이너에는 넣지 않는다**(`.env.docker`에도 넣지 않음). 요청 경로에 키움 호출이 없으므로 사용자 수가 늘어도 호출량 불변. 키 보관·허용 목록은 3-6절.
- 키가 없거나 `STOCKON_PRICE_SOURCE=public`이면 수집기의 키움 부분은 **꺼진 상태**(공공·DART·뉴스만 수집). 1단계는 이 상태로 운영한다.
- 저장: 위젯별 최신 스냅샷(`fetched_at`, `as_of`(데이터 기준 시각), `source`, `status`) + 30일 이력. ailab에는 볼륨을 읽기 전용으로 연결.
- HF 예비 AI LAB에는 수집기·키·볼륨이 없음 → STOCK:ON은 "오라클에서 제공" 안내만 표시(같은 코드, 데이터 없음 상태).

### 3-2. 호출 예산 (실전 한도 5회/초의 10% 이하로 운용)

| 묶음 | 주기(장중) | 호출 수 |
|---|---|---|
| 지수 2개(`ka20001`) | 5분 | 2 |
| 등락률 상위(코스피/코스닥 × 상승/하락) + 거래대금 상위 | 5분 | 5~6 |
| 히트맵 시총 상위 100 | 5분 | `ka10095` 묶음이면 2~4, 아니면 `ka10001` 100 |
| 팀 관심 종목(≤30) | 5분 | 1~30 |
| 외국인·기관(`ka90009`, `ka10051`) | 15분 | 3~4 |

- 최악(묶음 조회 불가)에도 5분에 약 140회 = **0.5회/초**. 429면 지수 백오프 후 그 주기는 건너뜀(이전 스냅샷 유지).
- **모의 키 기준(기본)**: 같은 TR은 **최소 1.1초 간격**으로 줄 세워 호출(TR 1개당 1초 1회 한도). 가장 많은 `ka10001`도 100회 ≈ 110초라 5분 주기 안에 끝난다. `ka10095`로 묶어 받을 수 있으면 수 초. 실전 키로 바꾸면 간격만 0.3초로 줄인다(설정값 하나).

### 3-4. 장 마감·휴장일 처리

- **2중 판정**: ① 연간 KRX 휴장일 파일(`data/stockon/krx_holidays_YYYY.json`, 매년 12월 갱신 — 공휴일·근로자의날·연말 휴장 포함) ② 실행 중 확인: 지수 응답의 거래일자가 오늘이 아니면 휴장으로 간주.
- 휴장·장 마감 후 화면: 마지막 거래일 스냅샷을 그대로 보여주고 상단에 **"휴장 · 10/24(금) 마감 기준"** 배지. 숫자를 비우지 않음.
- 장 시작 전(~09:00): "전일 마감 기준" 배지. 데이터 지연·실패 시: 이전 스냅샷 + "마지막 확인 HH:MM" 경고, 실패 원인은 관리자 화면에만.

### 3-5. AI 생성물 (브리핑·왜 움직였나·뉴스 요약)

- 입력은 **수집된 숫자 + 뉴스 제목/검색 요약문 + 공시 제목**만. 기사 원문은 저장하지 않는다.
- 출력 규칙(시스템 프롬프트 + 저장 전 검사):
  - 사실 서술만. 금지 표현 목록(매수·매도·사라·팔아라·담아라·추천·목표가·비중 확대/축소·저평가/고평가 단정·수익 보장 등)이 나오면 다시 생성, 2회 실패 시 해당 문장 제거.
  - **문장마다 출처 번호**, 하단에 출처 링크(뉴스 URL, DART 공시 URL, 데이터 출처명·기준 시각).
  - 근거가 없으면 "확인된 원인 없음 — 수급·시장 전반 영향일 수 있음"으로 표시(추측 금지).
- 비용·남용 방지: 브리핑은 수집기가 정해진 시각에만 생성. "왜 움직였나"는 **(종목, 날짜, 시간대) 캐시**, 첫 클릭 때 생성 후 공유, 하루 상한(예: 150건)과 사용자별 분당 제한.

### 3-6. 키움 연동 보안 설계 (조회 전용·키 비노출)

**① 조회 TR 허용 목록 — 코드에는 이것만 존재한다**

키움 공식 스펙의 URL 묶음 중 STOCK:ON이 쓰는 것은 아래 15개뿐이다. api-id와 URL을 **쌍으로 고정**한다(같은 URL에 다른 api-id를 넣는 것도 막음).

| URL | 허용 api-id |
|---|---|
| `/oauth2/token`, `/oauth2/revoke` | `au10001` 토큰 발급, `au10002` 토큰 폐기 |
| `/api/dostk/sect` | `ka20001` 업종현재가, `ka20009` 업종현재가일별, `ka10051` 업종별투자자순매수 |
| `/api/dostk/rkinfo` | `ka10027` 등락률상위, `ka10032` 거래대금상위, `ka10030` 거래량상위, `ka90009` 외국인기관매매상위 |
| `/api/dostk/stkinfo` | `ka10001` 주식기본정보, `ka10095` 지정종목정보, `ka10099` 종목정보 리스트, `ka10101` 업종코드 리스트 |
| `/api/dostk/frgnistt` | `ka10008` 외국인종목별매매동향, `ka10131` 기관외국인연속매매 |

**코드에 아예 넣지 않는 것**(문자열·함수·예제·SDK 모두):
- 주문: `/api/dostk/ordr`(kt10000~), `/api/dostk/crdordr`(신용주문), `/api/us/ordr`, 환전 `/api/us/exchange`
- 계좌: `/api/dostk/acnt`(33개, 잔고·체결·손익 등), `/api/us/acnt`
- 개인 관심종목 그룹: `/api/dostk/watchlist`(계좌 사용자의 HTS 관심종목 = 개인 정보)
- 실시간 WebSocket 전체(`wss://…:10000`, 주문체결 `00`·잔고 `04` 포함), 조건검색
  - **10-29 사용자 결정으로 변경**: '오늘 시장' 실시간 장중 동향을 위해 시세 타입 `0B`(주식체결)·`0J`(업종지수)·`0U`(업종등락)만 받는 웹소켓을 `services/stockon/kiwoom_realtime.py` 한 곳에 둔다(주문체결·잔고·조건검색은 여전히 없음, `NoOrderOrAccountCodeTest`가 확인). 조회 TR에 `ka20003`(전업종지수)·`ka20005`(업종분봉) 추가.
- 미국주식 전체

구현 원칙:
- 키움 공식 SDK(`kiwoom` 패키지·MCP·CLI)는 **설치·복사하지 않는다**. 주문 함수가 들어 있기 때문. `httpx`로 직접 만든 작은 클라이언트 하나(`services/stockon/kiwoom_client.py`)만 둔다.
- 클라이언트의 공개 함수는 `query(api_id, body)` **하나**. 내부의 `ALLOWED = {api_id: url}`(불변)에 없으면 **네트워크 호출 전에 예외**. 임의 URL·메서드를 받는 범용 요청 함수는 만들지 않는다.
- 도메인은 설정값 `KIWOOM_MODE=mock|real`로만 고른다(`mockapi.kiwoom.com` / `api.kiwoom.com`). 다른 호스트로 보내는 경로 없음.
- 응답은 TR별 **필드 허용 목록**만 꺼내 저장(가격·등락·거래량·순매수 등). 원문 응답·헤더는 저장하지 않는다.
- 테스트(네트워크 없이, 공식 스펙의 예시 응답 사용):
  1. `ALLOWED`의 모든 URL이 위 4개 묶음 + oauth뿐인지, 금지 묶음과 겹치지 않는지.
  2. 허용 목록 밖 api-id·URL 조합은 예외, HTTP 호출이 0회인지(가짜 전송기로 확인).
  3. **소스 검사**: `services/stockon/`·수집기·웹 코드 어디에도 `/ordr`, `/crdordr`, `/acnt`, `/watchlist`, `/websocket`, `/api/us/`, `kt1`, `kt5`, `ust2`, `wss://` 문자열이 없는지(이 테스트 파일 자신은 제외).
- 추가 안전장치(선택): 실전 키를 쓰게 되면 그 키를 **예수금이 없는 계좌**에 연결하면, 만일의 경우에도 주문이 체결될 수 없다. 키움이 "조회 전용" 키 권한을 제공하는지는 6절에서 문의.

### 3-7. 시세 출처 전환과 공공데이터 복귀

| 설정 | 값 | 동작 |
|---|---|---|
| `STOCKON_PRICE_SOURCE` | `public`(기본) | 공공데이터 T+1만 사용. 키움 호출 0회 |
| | `kiwoom` | 키움 장중 스냅샷 사용. **키움 스냅샷이 없거나 30분 넘게 갱신 실패하면 화면은 자동으로 공공데이터 스냅샷을 보여주고** 출처·기준 배지도 공공으로 바뀐다 |

- 출처 표시: 키움 데이터 → "KRX 기준 · 키움증권 API · HH:MM 반영", 공공 → "금융위원회 공공데이터 · MM/DD 종가(전일 기준)".

## 6. 키움에 확인할 질문 (고객센터·REST API 문의 — 참고용, 답변을 기다리지 않음)

2. 된다면 조건(지연 시간, 출처 표기, 이용 인원, 별도 계약·시세 이용료). 안 된다면 KRX/코스콤 정보이용계약이 필요한지.
3. 「오픈 API 서비스 이용약관」 전문(특히 정보 이용 범위·제3자 제공 조항).
4. 모의투자 App Key로 시세 조회 TR(`ka20001`, `ka10027`, `ka90009`, `ka10095` 등 — 공식 스펙에 모의 도메인 표기됨)이 **실제 KRX 시세와 같은 값**으로 응답하는지, 지연이 있는지.
5. 실서버 접속 없이 **모의 서버만** 쓰면 자동 해지 대상인지("모의투자 서버로만 로그인하신 경우 서비스가 자동 해지될 수 있습니다"), 해지되지 않으려면 무엇이 필요한지.
6. App Key를 **조회 전용(주문·계좌 API 불가)**으로 발급하거나 권한을 제한하는 방법이 있는지.
7. **모의투자 App Key도 IP 등록이 필요한지**, 필요하다면 "계좌 App Key 관리"에 등록한 IP(140.245.88.198)가 모의 키에도 적용되는지. 모의 키 관리 화면에는 IP 입력 칸이 없음.

- "STOCK:ON 상태": 마지막 수집 시각·실패 횟수·오늘 AI 생성 건수(값만, 키·원문 없음).
- 공개 범위는 기존 "서비스별 공개"에서 STOCK:ON 선택.
