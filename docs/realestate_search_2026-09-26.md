## 추가 조건에 필요한 데이터

현재 응답에는 가격, 전용면적, 층, 준공연도, 주소가 있다. 다음 단계는 전용면적 범위, 준공연도 범위, 층 조건을 우선 구현할 수 있다. 누락은 미확인으로 유지한다.

역 거리: 건물 좌표와 역 출입구 좌표를 연결한 뒤 직선거리(예: 500m/1km)를 명시해 제공할 수 있다. 도보거리·도보시간은 별도 경로 데이터가 있어야 한다. 직선거리를 도보시간으로 환산해 확정하지 않는다.

초등학교: 우선 학교 인접 거리로 제공 가능하지만 실제 배정 학교는 교육청 통학구역을 대조해야 한다. 학교 가까움만으로 초품아 확정 금지. 단지 출입구, 학교 출입구, 큰길 횡단 등 통학경로까지 확인해야 한다. 현재 좌표·통학구역 자료가 없어 동작하지 않는 필터를 노출하지 않았다.

주차대수/세대수/관리비/승강기 등은 공동주택 단지 원장 연계가 필요하다. 건물 식별자를 먼저 확정하고 source/evidence/confidence 및 확인일과 함께 저장하는 별도 보강 작업이 필요하다.

## 지역 선택 UX 재수정

상위 서울/경기는 목록 전환만 한다. 하위에 서울 전체/경기 전체 버튼을 둔다. 전체 선택 상태에서는 개별 칩들을 선택 표시하지 않고 전체 버튼만 표시한다. 개별 지역을 누르면 해당 범위 전체 선택을 그 지역 하나로 전환하며, 다른 시도의 선택은 유지한다. 이 지역 선택 해제/모두 해제로 한 번에 초기화할 수 있다. 이전 자동 전체 선택 동작을 대체한다.

청약 조회에도 동일한 하위 전체/개별 전환 UI 적용. 서울+경기 69개 지역을 전송할 수 있도록 SubscriptionQuery 지역 목록 최대 길이를 60에서 100으로 확장했다. 청약 원본 조회 방식은 동일하며 지역 수만큼 API 호출을 늘리지 않는다. 미선택은 기존과 같이 전체 청약 조회다.
