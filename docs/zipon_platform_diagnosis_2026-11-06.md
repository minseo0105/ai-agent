# ZIP 재개발 투자정보 플랫폼 고도화 — 1단계 현황 진단 (2026-11-06)

코드·마이그레이션·문서·직접 실행한 테스트와 운영 확인(2026-11-06 오전)에 근거한다.
"운영 미확인"은 이 저장소만으로 알 수 없는 항목이다. API 키·개인정보는 기록하지 않았다.

## 1. 기술 구조

| 영역 | 현황 |
|---|---|
| 프론트엔드 | Next.js 16 + React 19 + Tailwind 4 (정적 내보내기), `leaflet` 의존성 있으나 지도는 NAVER Maps JS v3 Dynamic Map |
| 백엔드 | FastAPI (`api/realestate.py`), 실거래·청약·개발정보 `/api/realestate/*` |
| DB | Supabase(PostgreSQL + PostGIS). 모든 테이블 RLS 켬, `anon`/`authenticated` 권한 없음, 서버(`service_role`)만 접근 |
| 인증 | 관리자 토큰 + 관리자가 발급한 구성원 개인 접속 코드(HMAC 토큰). Supabase Auth 사용자 없음 |
| 수집 | `services/development_collector.py`·`development_refresh.py`, GitHub Actions `zipon-development-refresh.yml`(매일 07:17 KST), `realestate-monitor.yml` |
| 화면 | `/realestate` 한 페이지(최대 폭 4xl)에 탭 5개: 개발지도·실거래 조회·청약 조회·모니터링 조건·알림함 |

## 3. 막힌 지점과 위험

1. **Polygon 표시의 선결 조건**: 검증된 경계 0건. 켜면 "구역 안" 판정이 생겨 투자 판단에 영향이 크다. DB 쓰기·승인이 필요한 별도 트랙.
2. **법적 진단은 가장 위험한 기능**: 잘못된 "제한 없음" 표시가 실제 피해로 이어진다. 데이터(법령·규제지역)가 없는 상태에서 판정을 만들 수 없다. 정보 부족 시 "추가 확인 필요"가 기본값이어야 한다.
3. **거래 저장소 부재**: 구역 안 거래 분류·추이·알림 모두 외부 API를 매번 부르거나 별도 저장이 필요하다.
4. **사용자 모델**: Supabase Auth가 없어 "관심 구역"은 구성원 접속 코드 토큰에 매다는 방식이 된다.
5. **검토 대기 994건**: 단계·날짜가 모호한 프로젝트가 많아 타임라인의 "실제 인가일"이 비어 있는 구역이 많을 것.
