# MONEY:ON 개발 보고서

## Hugging Face Spaces 배포 준비 (Phase 5)

현재 배포 방식은 사용자 웹 로그인·직접 Space 생성·웹 파일 업로드를 우선한다. [웹 업로드 파일 목록과 절차](MONEYON_WEB_UPLOAD.md)에 40개 파일 ZIP, 새 MONEY 전용 GitHub 저장소용 43개 파일 ZIP, Secret 직접 등록과 수동 Actions를 정리했다. HF CLI 로그인은 사용하지 않으며 실제 업로드는 아직 수행하지 않았다.

기존 AI LAB Docker 배포와 분리된 MONEY 체험 전용 Space 구성을 추가했다. 화이트리스트 소스 번들, Next 정적 export, 체험 API만 등록하는 FastAPI, UID 1000·7860 Dockerfile, 기본 dry run 업로드 명령과 수동 Docker CI를 제공한다. 실제 생성·업로드는 사용자 승인 전이라 수행하지 않았다. Docker 및 실제 HF 실행 미검증 항목을 포함한 분석·실행 명령·환경변수·URL·Git 정리는 [Phase 5 배포 준비 보고](MONEYON_SPACES.md)를 참조한다.

## 완성형 샘플 통장 자유 체험 (Phase 4)

첫 화면의 **바로 체험하기**는 PIN·부모 등록·자녀 등록 없이 이미 거래가 채워진 하늘의 통장을 연다. **부모님과 직접 시작하기** 및 기존 AI LAB 로그인·가족 데이터는 보존했다. 체험 전용 DB와 방문자별 비밀 토큰으로 실제 가족과 다른 방문자의 원장을 격리한다.

실제 Mock Ledger의 초기 잔액은 통장 **28,500원**, 저금통 **15,000원**, 총 **43,500원**이다. 예상 보상 **800원**은 기존 계산 엔진의 신규 용돈 10%·회차 한도 800원으로 산출하며 확정 잔액에 포함하지 않는다. 금액 입력으로 용돈 받기·소비·저축, 가상 날짜와 부모 승인 시뮬레이션, 확인 후 원자적 초기화를 지원한다.

구현 구조, 이전 회차의 유효한 보상 시드, 세션·탭·재접속 정책, 실행 설정, 테스트와 화면 캡처는 [Phase 4 완료 보고](MONEYON_TRIAL.md)를 참조한다. 현재 체험 동작은 이 문서가 이전 단계 설명보다 우선한다. 운영 DB 변경·배포·Git push는 하지 않았다.

## 어린이 UI/UX와 금융 코치 리브랜딩 (Phase 3)

어린이 하단 메뉴를 홈·통장·저축 세 개로 통합했다. 홈은 인사→통장 잔액→저금통/예상 보상→돈 썼어요/통장 보기→최근 거래 최대 3개→나의 성장→금융 친구의 짧은 메시지 순서다. 기입장과 분류 수정은 통장, 정원·퀘스트·배지는 나의 성장, 이자 실험은 저축의 이자 알아보기에 통합했다. 기존 부모 화면과 금융 데이터는 유지한다.

금융 친구 기본 시안은 **우루미(WOORUMI)**다. 표시명·브랜드 문구는 `web/src/lib/moneyonCoach.ts` 한 곳에서 설정하며, 여섯 상태의 오리지널 SVG와 규칙 기반 설명을 사용한다. 우리금융 공식 캐릭터라고 표시하지 않는다. 금융 원장·Mock Banking·이자 계산·API 소스 다섯 파일의 SHA-256이 작업 전후 일치함을 확인했다.

화면 구조·변경 파일·브랜드 변경 방법·검증·모바일 캡처·미해결 사항은 [Phase 3 결과 보고](MONEYON_CHILD_UX.md)를 참조한다. 아래 이전 단계 설명과 메뉴 구성이 다르면 Phase 3 문서를 우선한다.

## 은행 앱 연계형 프로토타입 확장 (Phase 2)

기존 기능을 보존하면서 부모·자녀 가상 통장, 동일 이체 ID의 원자적 출금·입금, 가상 가맹점 소비, 통장과 기입장의 자동 연결, 카테고리 정정 이력, 부모 보상 이자 출금, 금고 분개를 추가했다. 잔액은 이제 계좌 분개 합계에서 계산하며 기존 용돈 이벤트·이자 엔진을 그대로 사용한다. 기존 거래를 한 번 이관하며 과거 지급액을 부모 계좌에서 다시 차감하지 않는다.

DEMO 전용 가족 공간에는 부모 500,000원, 재현(매주 10,000원·10%), 서연(매월 30,000원·5%)을 준비한다. `MONEYON_DEMO=1`에서만 시연 가족 생성·가상 날짜·새 시연 가족 만들기를 허용한다. 초기화는 현재 데모를 보관하고 새 공간을 생성하며 기존 가족이나 데모 거래를 삭제하지 않는다. 실제 은행 API는 연결하지 않았다.

상세 변경 파일·모델·API·검증·실행 방법·남은 위험은 [은행 프로토타입 설계 및 결과](MONEYON_BANKING.md)에 정리했다. 아래 Phase 1 기록의 잔액 계산·테이블 설명은 이 문서의 Phase 2 설명을 우선한다.

## 구현 범위

Phase 1 용돈 원장, Phase 2 은행 시뮬레이션을 유지하면서 Phase 3 어린이 UI와 금융 친구를 개선했다. 정원·배지·퀘스트·공동 미션·월간 리포트의 기본 기능도 유지한다. 운영 서비스 전체 완성 또는 최초 기획의 모든 세부 요구사항 완료를 의미하지 않는다.

운영 배포, 원격 push, 기존 운영 데이터 변경, 외부 유료 서비스 연결은 수행하지 않았다.

## 1. 기존 프로젝트 분석

- 기존 서비스: Next.js 16 / React 19 / TypeScript / Tailwind 화면, Python FastAPI API. 이전 Streamlit 화면도 공존한다.
- 웹 진입: `web/src/app/page.tsx`, 서비스 목록 `web/src/lib/services.ts`, 웹 라우팅은 App Router.
- 카드: `web/src/components/ServiceGrid.tsx`, `home/catalog.ts`, `home/ServiceArtwork.tsx`. 작업 중 별도 홈 개편이 관찰되어 기존 변경을 유지하며 신규 항목만 추가했다.
- 서버 진입: `api/main.py`, 라우터별 모듈을 include. 정적 export가 있으면 FastAPI에서 함께 제공한다.
- 인증: `services/access.py`의 기존 서명 토큰과 구성원 ID를 재사용한다. 공개 화면 접근과 가족 금융 데이터 접근은 구분한다.
- 기존 저장: 서비스에 따라 Supabase 또는 로컬 저장. MONEY:ON 개발 DB는 기존 DB와 분리했다.
- 환경설정: 기존 API `get_secret`, 웹 `NEXT_PUBLIC_API_URL`. MONEY:ON의 개발 허용 설정은 서버 환경변수로 명시한다.
- 배포: 기존 Docker·deploy 구성 유지. MONEY:ON 운영 DB 마이그레이션이나 배포 변경은 하지 않았다.
- 브랜치: 작업 시작 시 `codex/zipon-live-refresh`. 다수의 기존 staged/unstaged 변경을 보존했고 커밋·reset·push를 수행하지 않았다.

## 2. 메뉴와 화면

AI LAB에 MONEY:ON 카드와 직접 만든 민트 저금통 SVG를 추가했다. `/moneyon`은 기존 접근 게이트 및 서비스 공개 범위 설정에 연결된다.

부모 흐름: 시작 → 기존 AI LAB 접속 코드 → PIN → 가족 대시보드 → 3단계 자녀 등록 → 아이 선택 → 현재 주기 용돈 지급 → 종료 후 보상 이자 승인. 아이 정보·학년·테마·캐릭터·정책 변경, 중지·재개·보관, 월간 소비 리포트와 사유를 남긴 지출 취소를 제공한다.

어린이 흐름: 부모가 아이 선택 → 해당 아이에만 유효한 세션 → 홈 / 기록 / 저축 / 퀘스트 / 정원. 홈에서 실험실·코치에 진입할 수 있다. 모바일 하단에는 주요 메뉴 5개를 고정한다. 소비 내역과 배지는 탭·정원에 통합했다.

민트·블루·핑크 테마는 동일한 원장을 공유한다. 로딩·오류·빈 가족·빈 거래 상태, 큰 숫자와 터치 버튼, 키보드 포커스, reduced-motion 처리를 제공한다. 이미지 기반 3D 캐릭터 대신 현재 버전은 이모지와 SVG를 사용한다.

## 3. 금융 계산 및 날짜 정책

- 금액은 정수 원. 이자율은 정수 basis point로 저장한다. UI의 100은 1%, 1000은 10%다. 부동소수점 금융 계산은 사용하지 않는다.
- `보상 = min(적격 잔액 × rate_bps // 10000, 상한액)`.
- 주간은 월요일 0~일요일 6. 월간은 1~31일이며 해당 월에 없으면 마지막 날짜를 사용한다. 시작일 포함, 종료일 제외.
- 지급은 부모가 버튼으로 확인하는 수동 지급이다. 지급일은 자동이체 예약이나 실제 현금 지급을 의미하지 않는다. 지난 날짜의 미지급분을 자동 소급 지급하지 않는다.
- 현재 주기는 설정한 정기 지급일을 기준으로 정한다. 정책은 지급 시 스냅샷을 저장한다. 지급 후 정책을 바꿔도 기존 계산은 유지된다. 새 정책 주기가 기존 지급 주기와 겹치면 차단한다.
- 신규 용돈부터 소비한 것으로 계산한다. 이월금·기존 보상금·금고는 이자 대상에 추가하지 않는다. 금고로 옮긴 신규 용돈은 적격 잔액에서 빠지며, 다시 꺼내도 복구되지 않는다.
- 이자는 부모 승인 전 지갑에 반영하지 않는다. 주기 종료 뒤 미정산 상태에서는 지급·지출·금고 이동을 막아 종료 잔액을 유지한다. 부모가 먼저 정산해야 한다.
- 이월하지 않는 정책은 해당 주기의 미사용 적격 용돈을 회수하는 별도 원장 항목을 남긴다. 금고나 과거 이월금을 임의로 회수하지 않는다.
- 진행 중 지출은 부모가 사유와 함께 취소할 수 있다. 원본과 역거래를 모두 보존한다. 정정은 취소 후 새 지출을 등록한다. 종료·정산한 주기는 현재 버전에서 지출 취소를 허용하지 않는다.
- 실험실과 모니 코치는 서버의 동일 계산 함수를 사용한다. 슬라이더는 200ms 지연 후 자동 계산하며 원장에 기록하지 않는다.
- API의 주기 기준일과 거래 생성 시각은 한국 시간 기준이다.

예시: 10,000원 지급, 4,000원 소비, 10% 보상 → 잔액 6,000원, 예상 600원, 종료·부모 승인 후 6,600원. 금고에 추가로 1,000원을 옮겼다면 지갑 5,000원 / 금고 1,000원 / 예상 보상 500원이 된다.

## 4. 데이터베이스

`data/moneyon/development.sqlite3`에 SQLite 스키마를 멱등 생성한다. 해당 디렉터리는 Git에서 제외된다. DB 경로는 `MONEYON_DB`로 바꿀 수 있다. 기존 Supabase 스키마나 운영 DB는 변경하지 않았다.

| 테이블 | 역할 |
|---|---|
| moneyon_schema | 스키마 버전 1 |
| families | 가족 식별자, salt, scrypt PIN 해시, 실패 횟수·잠금 |
| children | UUID, 소유 가족, 프로필·테마, 다음 지급 정책, 이용 상태 |
| cycles | 지급 주기, 정책 스냅샷, 최초 적격액, 정산 여부 |
| transactions | 지급·지출·금고 이동·이자·회수·취소·적격액 변경의 불변 원장 |
| goals | 아이별 저축 목표 |
| sessions | 가족·아이 범위와 만료 시간이 있는 인증 세션 |
| quest_progress | 중복 보상 없는 아이별 퀘스트 정답 기록 |

요청서의 지급·저축 이체·정산·승인 이력은 통합 원장의 거래 종류와 주기 상태로 구현했다. 테마는 프로필, 배지·XP·공동 미션은 원본 기록에서 파생한다. 요청서의 14개 논리적 테이블을 각각 물리 테이블로 생성하지는 않았다.

SQLite `BEGIN IMMEDIATE`로 조회·검증·거래 기록을 한 트랜잭션에서 수행한다. `(child,start)` 고유 제약과 겹침 검증으로 중복 지급을 막고, `(child,request_key)`로 재전송을 중복 처리하지 않는다. 정산 여부도 동일 트랜잭션에서 검사·갱신한다. Phase 2부터 화면 잔액은 계좌 분개 `bank_postings.amount` 합계로 계산한다. 기존 wallet/vault 이벤트 합계와 일치하는지 자동 테스트로 검증한다. 추가 모델은 별도 은행 설계 문서를 참조한다.

## 5. 권한·개인정보

- 서버에서 기존 AI LAB 인증을 확인하고 `member:<구성원 ID>`를 가족 식별자로 사용한다. 기존 관리자 계정은 로컬 개발 전용 `admin:local` 가족으로 연결된다. 다수의 실제 부모를 공용 관리자 계정에 연결하면 안 된다.
- PIN은 6~12자리 숫자이며 salt + scrypt 해시로 저장한다. 5회 실패하면 5분 잠근다. 부모 세션은 15분, 아이 세션은 1시간이다.
- 첫 인증된 가족 사용자가 PIN을 등록한다. PIN 변경·복구와 독립적인 운영 부모 온보딩은 후속 작업이다.
- 아이 선택 시 부모 세션을 폐기한다. 아이 세션은 다른 아이 조회, 부모 목록 조회, 정책 변경, 지급, 정산, 지출 취소를 수행할 수 없다.
- 아이가 중지·보관되면 기존 아이 세션도 사용할 수 없다. 금융 작업은 항상 가족 소유권과 아이 상태를 재검사한다.
- 별명·학년·기본 캐릭터만 수집한다. 은행, 결제, 외부 LLM 연결은 없다. 코치는 규칙 기반으로 동작한다.
- `MONEYON_LOCAL_DEV=1`이 없거나 `APP_ENV=production/prod`이면 API가 503으로 차단된다. 이 버전은 운영 인증·저장소 준비 전 로컬 개발용이다.

## 6. 게임·교육 기본 구현

기록한 날짜 수, 목표 생성, 퀘스트 최초 정답으로 XP를 계산한다. 같은 날 지출을 잘게 나눠도 기록 XP는 하루 한 번이다. 금액 자체로 XP가 오르지 않는다. 50 XP 단위로 씨앗→새싹→작은 나무→큰 나무→열매 나무→황금 저축 나무가 된다. 기록·목표·퀘스트·3일 기록 배지를 제공한다.

퀘스트는 실제 기록·목표 활동과 두 가지 선택형 문제다. 저학년은 1,000원의 10%, 고학년은 15,000원의 5%를 묻는다. 오답은 힌트를 주고 다시 도전하며 정답을 중복 제출해도 XP가 늘지 않는다. 가족 미션은 모두 목표 만들기 / 모두 이번 달 3일 기록이며 금전 보상이 없다. 형제자매 순위는 제공하지 않는다.

목표 진행률은 각 목표를 같은 금고 잔액과 비교하며 화면에 이를 명시한다. 목표별로 자금을 별도 배분하는 기능은 아직 없다. 달성 예상일을 계산할 충분한 기록 모델은 아직 구현하지 않았으며 임의 날짜를 표시하지 않는다.

## 8. 로컬 실행

기존 API 환경의 의존성이 설치되어 있어야 한다. 현재 머신의 `.venv`만으로 일부 기존 에이전트 의존성을 충족하지 못할 수 있으므로 기존 프로젝트 실행 환경을 사용한다. MONEY:ON 자체는 새로운 Python 라이브러리를 추가하지 않는다.

PowerShell, 프로젝트 루트:

```powershell
$env:MONEYON_LOCAL_DEV='1'
$env:APP_ENV='development'
.venv/Scripts/python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

별도 터미널:

```powershell
cd web
npm run dev
```

`http://localhost:3000/moneyon`에서 기존 AI LAB 개인 접속 코드로 로그인한 뒤 부모 PIN을 최초 등록한다. 사이트가 등록자 전용이라면 기존 접근 게이트에서 먼저 로그인한다. 관리자는 기존 `/admin` 인증을 이용할 수도 있다. 실제 자녀 개인정보 대신 테스트 별명을 사용한다.

전체 웹 빌드·타입 검사:

```powershell
cd web
npm run typecheck
$env:NEXT_BUILD_DIR='.next-moneyon'
npm run build
```

원장·API 자동 테스트:

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p test_moneyon.py -v
```

브라우저 테스트는 기존 `reports/analytics-browser/node_modules/playwright`와 설치된 Chrome을 사용한다. 테스트 전 `.next-moneyon` 빌드가 있어야 한다.

```powershell
node tests/test_moneyon_browser.cjs
```

이 테스트만 격리된 가족 인증을 주입하며 실제 PIN·아이 세션·SQLite 원장·계산 API를 사용한다. 한국 시간 기준 테스트 날짜를 별도 fixture API로 이동한다. fixture는 `api.main`에 포함되지 않는다. 테스트 서버는 loopback의 3107·8107 포트에만 열고 종료 시 닫는다. 테스트 DB는 Git 제외된 `data/moneyon/browser-*`, 화면 증거는 `reports/moneyon`에 남는다.

## 9. 검증 결과

- 원장·API: 동일 이름 다자녀, 가족/아이 권한, 주·월 지급일, 윤년 외 월말·연도 경계, 중복 지급, 잔액 초과, 지출 취소 원본 보존, 소수점 거절, 이자 버림·상한, 정책 스냅샷, 예상/확정 분리, 동시 승인 1회, 이월 제외, 미정산 잠금, 금고 합계·재진입 이자 제외, 목표 저장, 테마 변경 잔액 보존, 중지·보관, 멱등 스키마 생성, 퀘스트 중복 보상 차단, 부모/아이 세션 폐기를 자동 검증했다.
- 최신 MONEY:ON 테스트 32개 실행 통과(아이 세션 잠금 API 검증 포함). API 테스트 클래스가 기본 원장 테스트를 상속하므로 공통 시나리오 일부는 두 번 실행된다.
- 기존 UI·분석 API·사용현황 + MONEY:ON 합계 148개 통과.
- 기존 analytics 프런트엔드 전송·개인정보·중복방지 테스트 통과.
- 웹 타입 검사 통과, 전체 Next 빌드 통과 및 `/moneyon` 경로 생성 확인.
- 브라우저에서 동일 이름 두 자녀, 주간/월간 지급, 4,000원 소비 후 아이별 분리, 슬라이더의 서버 계산과 원장 비변경, 금고·목표·퀘스트·배지, 한국 날짜의 다음 주기로 이동 후 이자 1회 승인, 메인 카드 진입을 통과했다. 375·768·1440px에서 가로 넘침 없음과 브라우저 런타임 오류 없음도 확인했다. 결과와 화면은 `reports/moneyon/browser-result.json` 및 스크린샷을 참고한다.

기존 골프·부동산 외부 API의 실제 운영 데이터 연결, 모든 기존 에이전트의 실사용 기능, 실제 모바일 기기의 터치·보조기술 접근성, 운영 인증·DB 마이그레이션·배포는 미검증이다. 테스트 중 Windows 임시 폴더 및 프로세스 생성 제한으로 권한을 부여해 재실행했다. 현재 코드에 대한 배포 승인으로 해석하면 안 된다.

## 10. 후속 개선과 운영 전 조건

- 운영용 부모 계정/가족 가입·초대·동의·복구, PIN 변경·복구 및 감사 정책.
- 영속 DB 선택, 명시적 버전 마이그레이션·백업·복구·데이터 보관/삭제, 운영 다중 인스턴스 동시성 검증. SQLite 개발 DB를 그대로 운영 저장소로 전환하지 않는다.
- 요청서 21개 화면 중 통합 탭으로 제공하는 프로필·테마/배지/부모 설정의 독립 화면, 초기 잔액 입력, 목표 이미지·희망일·수정·배분, 실제 저축 속도 기반 예상일.
- 정원 꾸미기 아이템·보물상자/목표 달성 애니메이션, 계획소비·연속 기록·목표 달성 기반 성장 강화, 더 넓은 연령별 퀘스트와 주간 공동 미션.
- 주간·월간 비교 리포트와 저축률 추이, 기록 참여율 분모의 명시, 과거 대비 교육 코멘트.
- 지출 정정의 원자적 교체, 종료된 주기의 부모 조정 원장, 정책 변경/이월 회수에 대한 더 상세한 안내.
- 운영이 필요하면 개발 전용 차단을 먼저 해제하지 말고 인증·저장소 설계를 완료한다. 자동 지급 스케줄러 및 외부 LLM은 현재 연결하지 않았다.
