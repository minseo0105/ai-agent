# STEP 5-B: 검색 요약문의 후기 표현 분석

현재 골프 페이지는 레이크사이드CC에 한해 로컬 규칙으로 난이도·페어웨이·그린·코스관리·시설을 분석한다. 기존 공공데이터 기본정보는 그대로 사용한다. 캐디, 보조항목, 자연어 추천, 다른 골프장 분석은 제공하지 않는다.

## 실행 경로

`pages/6_골프장_추천.py` → `services/golf_expressions.py` → 기존 `services/golf_api.py`의 `collect_reviews`.

버튼을 누르기 전에는 호출하지 않는다. 최초 검색은 `레이크사이드CC 라운딩 후기`, `display=100`이다. 이후 독립 유효 근거 2건 미만인 항목만 한 번씩 추가 검색한다. 실패를 포함해 세션당 최대 6회이며 자동 재시도·페이지 순회는 없다. 완료 후 화면 재실행은 결과를 표시하기만 한다.

Endpoint는 `https://naverapihub.apigw.ntruss.com/search/v1/blog`이며, 인증 헤더는 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY`이다. 기존 Secrets 해석과 인증 코드는 변경하지 않는다. 인증값을 출력하지 않는다.

## 근거와 판정

- 제목·검색 요약문에서 HTML을 제거하고 원문 URL은 그대로 유지한다.
- URL 비교용 정규화로 모바일/PC NAVER 블로그 링크를 중복 제거한다. 추가 검색에서 요약문이 달라져도 같은 URL은 한 근거다.
- 다른 골프장, 해외 동명 골프장, 주변 식당 소개는 제외한다. 명백한 판매·협찬 표현은 promotional, 장비 리뷰·홍보 여부가 불분명한 글은 uncertain으로 보류한다.
- 주어와 방향 표현이 인접해야 한다. 부정·질문·추측·해시태그·방향 불명확 표현은 uncertain으로 둔다. 예약 난이도, 주차장 폭, 경기 진행 속도를 코스 특성으로 사용하지 않는다.
- 항목별 양 방향 수와 uncertain 수는 고유 URL 수다. 한 글의 상충 방향은 uncertain이다. 같은 작성자의 여러 글은 독립 출처 하나이며 작성자 내부 상충은 독립 방향 집계에서 제외한다.
- 독립 유효 출처 2곳 미만은 정보 부족, 2~4곳의 단일 방향은 표본 적음이다. 5곳 이상이고 우세 방향 비중 80% 이상, 양 방향 차이 3곳 이상일 때만 해당 표현이 많이 확인됐다고 표시한다. 비중의 분모에는 방향을 판정할 수 없는 uncertain을 포함하지 않는다. UI에서 uncertain과 관련 후기 총수를 함께 보여준다.
- 강한 우세 조건에 못 미치고 양 방향 각각 2곳 이상이면 평가가 엇갈림, 양쪽이 존재하나 이 조건도 못 채우면 뚜렷한 경향 없음이다. 점수를 만들지 않는다.
- 동/남/서코스는 실제 제목·요약에 명시된 경우만 기록한다. 여러 코스가 섞여 귀속이 모호하면 코스별 방향 근거에서 제외한다. 전체 카드는 코스별 표현을 포함한 검색 표본의 분포이며 골프장 전체의 객관적 평가가 아니다.

## 저장 및 전송

검색결과·분석은 `golf_expression_session` session_state 안에만 유지한다. 파일·JSON·DB·Streamlit persistent cache에 쓰지 않는다. 세션 종료 시 소실될 수 있다. 원문 페이지를 수집하지 않으며 외부 LLM을 호출하지 않는다. 이 경로는 OpenAI 키를 읽지 않는다.

이전 단계의 `golf_analysis.py`와 이전 CLI 분석 기능은 현재 페이지 경로에서 사용하지 않는다. STEP 5-B 검증에 이전 `--analyze` 명령을 사용하지 않는다.

## 검증 명령

오프라인: `.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -p test_golf*.py -v`

명시적 실제 호출: `.venv/Scripts/python.exe -X utf8 scripts/verify_golf_step5b.py`

실제 검증 스크립트는 Streamlit AppTest 세션에서 버튼을 누른다. 버튼 전 네트워크를 금지하고 클릭 후 지정된 NAVER endpoint/헤더/display/호출 한도를 검사한다. 결과는 콘솔로만 보고하며 파일 리다이렉션을 사용하지 않는다. 앱의 기본정보·기존 API 파일 변경 여부도 해시로 검사한다. 실제 NAVER 결과나 파생 통계는 테스트 fixture나 문서에 저장하지 않는다.

## 해석상 한계

검색 결과는 라운딩 후기 전체를 대표하지 않는다. 최신순 검색에도 오래된 글이 포함될 수 있다. 생략된 문맥, 반어, 띄어쓰기, 다양한 어미, 홍보 표기 누락으로 오분류와 누락이 가능하다. 같은 작성자를 묶어도 서로 다른 작성자 간 복제 글까지 확인하지 못한다. 반대 방향 0건은 실제 부정 의견이 없다는 뜻이 아니다. 기준은 검증용 보수적 규칙이며 통계적 신뢰구간이나 학습된 정확도가 아니다.
